# 2.2 data abstraction

当我们思考世上想要在程序中表示的众多事物时，会发现它们大多具有复合结构。例如，一个地理位置有纬度和经度坐标。为了表示位置，我们希望编程语言能够把纬度和经度组合成一个 pair，即一个 *compound data* 值：程序可以把它当作单个概念单元来操作，同时它又有两个可以单独考察的部分。

使用复合数据能提高程序的模块化程度。如果我们可以把地理位置当作完整的值来操作，就能把程序中用位置做计算的部分与位置如何表示的细节隔绝开。把程序中处理“数据如何表示”的部分与处理“数据如何操作”的部分隔离开来，这一通用技术就是被称为 *data abstraction* 的强大设计方法。data abstraction 让程序更容易设计、维护和修改。

data abstraction 在性质上与 functional abstraction 相似。当我们创建一个 functional abstraction 时，function 的实现细节可以被隐藏，而某个具体的 function 本身也可以被任何具有相同整体行为的其他 function 取代。换句话说，我们可以做出一种 abstraction，把 function 的使用方式与它的实现细节分开。类似地，data abstraction 把复合数据值的使用方式与它如何构造的细节隔离开。

data abstraction 的基本思想是：以这样的方式组织程序，使它们作用于抽象数据。也就是说，我们的程序在使用数据时，应当对数据做出尽可能少的假设。与此同时，一个具体的数据表示被定义为程序中独立的一部分。

程序中的这两个部分——作用于抽象数据的部分和定义具体表示的部分——由一小组 function 连接起来，这些 function 用具体的表示来实现抽象数据。为了说明这一技术，我们将考虑如何设计一组用于操作有理数的 function。

## 2.2.1 例子：有理数

有理数是两个整数之比，它构成了实数的一个重要子类。像 `1/3` 或 `17/29` 这样的有理数通常写成：

```

<numerator>/<denominator>
```

其中 `<numerator>` 和 `<denominator>` 都是整数值的占位符。要精确刻画这个有理数的值，这两部分都必不可少。真正做整数除法会得到一个 `float` 近似值，从而失去整数所具有的精确性。

```python
>>> 1/3
0.3333333333333333
>>> 1/3 == 0.333333333333333300000  # Dividing integers yields an approximation
True
```

不过，只要把分子和分母组合在一起，我们就能为有理数建立一种精确的表示。

从使用 functional abstraction 的经验中我们知道，即使程序中某些部分还没有实现，我们也可以开始有效地编程。让我们先假设已经有了一种从分子和分母构造有理数的方法。我们还假设，给定一个有理数，我们能够取出它的分子部分和分母部分。再进一步假设，这个 constructor 和这些 selector 就是下面三个 function：

- `rational(n, d)` 返回分子为 `n`、分母为 `d` 的有理数。
- `numer(x)` 返回有理数 `x` 的分子。
- `denom(x)` 返回有理数 `x` 的分母。

这里我们用的是一种强大的程序设计策略：*wishful thinking*。我们还没有说有理数如何表示，也没有说 `numer`、`denom` 和 `rational` 这几个 function 应该如何实现。尽管如此，只要我们真的定义了这三个 function，就可以对有理数做加法、乘法、打印和相等性测试：

```python
>>> def add_rationals(x, y):
        nx, dx = numer(x), denom(x)
        ny, dy = numer(y), denom(y)
        return rational(nx * dy + ny * dx, dx * dy)
```

```python
>>> def mul_rationals(x, y):
        return rational(numer(x) * numer(y), denom(x) * denom(y))
```

```python
>>> def print_rational(x):
        print(numer(x), '/', denom(x))
```

```python
>>> def rationals_are_equal(x, y):
        return numer(x) * denom(y) == numer(y) * denom(x)
```

现在我们已经用 selector function `numer` 和 `denom` 以及 constructor function `rational` 定义了有理数的运算，但还没有定义这些 function 本身。我们需要的是某种把分子和分母粘合成一个复合值的方法。

## 2.2.2 pair

为了让我们能够实现 data abstraction 的具体层面，Python 提供了一种称为 `list` 的复合结构，它可以把若干 expression 放在方括号里、用逗号分隔来构造。这样的 expression 称为 list literal。

```python
>>> [10, 20]
[10, 20]
```

list 的 element 可以用两种方式访问。第一种方式是我们熟悉的多重赋值，它把一个 list 拆包成若干 element，并把每个 element 绑定到不同的名字。

```python
>>> pair = [10, 20]
>>> pair
[10, 20]
>>> x, y = pair
>>> x
10
>>> y
20
```

访问 list 中 element 的第二种方式是 element selection operator，它同样用方括号表示。与 list literal 不同，紧跟在另一个 expression 之后的方括号 expression 并不会求值为一个 `list` 值，而是从前一个 expression 的值中选出一个 element。

```python
>>> pair[0]
10
>>> pair[1]
20
```

Python 中的 list（以及大多数其他编程语言中的 sequence）的 index 都从 0 开始，也就是说 index 0 选出第一个 element，index 1 选出第二个，依此类推。支持这种 index 约定的一种直觉是：index 表示该 element 距离 list 开头有多远。

与 element selection operator 等价的 function 称为 `getitem`，它同样使用从 0 开始的位置来从 list 中选出 element。

```python
>>> from operator import getitem
>>> getitem(pair, 0)
10
>>> getitem(pair, 1)
20
```

在 Python 中，表示 pair 的方法并不只有两元素 list。任何把两个值打包成一个的方法都可以视为 pair。list 是实现这一点的一种常见方法。list 也可以包含多于两个的 element，我们将在本章后面探讨。

**表示有理数。** 现在我们可以把一个有理数表示为两个整数的 pair：一个分子和一个分母。

```python
>>> def rational(n, d):
        return [n, d]
```

```python
>>> def numer(x):
        return x[0]
```

```python
>>> def denom(x):
        return x[1]
```

结合我们前面定义的算术运算，现在可以用已定义的 function 来操作有理数了。

```python
>>> half = rational(1, 2)
>>> print_rational(half)
1 / 2
>>> third = rational(1, 3)
>>> print_rational(mul_rationals(half, third))
1 / 6
>>> print_rational(add_rationals(third, third))
6 / 9
```

如上面的例子所示，我们的有理数实现并没有把有理数约到最简形式。我们可以通过修改 `rational` 的实现来弥补这个缺陷。如果我们有一个计算两个整数最大公约数的 function，就可以用它先把分子和分母约到最简，再构造 pair。和许多有用的工具一样，这样的 function 在 Python 库中已经存在了。

```python
>>> from fractions import gcd
>>> def rational(n, d):
        g = gcd(n, d)
        return (n//g, d//g)
```

floor division operator `//` 表示整数除法，它会把除法结果的小数部分向下取整。由于我们知道 `g` 能整除 `n` 和 `d`，在这种情况下整数除法是精确的。这个修改后的 `rational` 实现保证有理数总是以最简形式表示。

```python
>>> print_rational(add_rationals(third, third))
2 / 3
```

这一改进只通过修改 constructor 就完成了，没有改动任何实现实际算术运算的 function。

## 2.2.3 abstraction barrier

在继续看更多 compound data 和 data abstraction 的例子之前，让我们先思考有理数这个例子提出的一些问题。我们基于 constructor `rational` 和 selector `numer`、`denom` 定义了运算。一般来说，data abstraction 的根本思想是：确定一组基本运算，某类值的所有操作都用这组运算来表达，然后只使用这些运算来操作数据。以这种方式限制运算的使用，就能在不改变程序行为的前提下，更容易地更换抽象数据的表示。

对于有理数，程序中不同的部分使用不同的运算来操作有理数，如下表所述。

| **程序中这样的部分……** | **它们把有理数视为……** | **只使用……** |
| --- | --- | --- |
| 使用有理数进行计算 | 完整的数据值 | `add_rational, mul_rational, rationals_are_equal, print_rational` |
| 创建有理数或实现有理数运算 | 分子和分母 | `rational, numer, denom` |
| 实现有理数的 selector 和 constructor | 两元素 list | list literal 和 element selection |

在上面每一层中，最后一列的 function 都维护着一条 abstraction barrier。这些 function 由更高的层次调用，并使用更低层次的 abstraction 来实现。

只要程序中本可以使用更高层次 function 的部分改用了更低层次的 function，就发生了 abstraction barrier 违例。例如，计算有理数平方的 function 最好基于 `mul_rational` 来实现，因为后者对有理数的实现不做任何假设。

```python
>>> def square_rational(x):
        return mul_rational(x, x)
```

直接引用分子和分母会违反一条 abstraction barrier。

```python
>>> def square_rational_violating_once(x):
        return rational(numer(x) * numer(x), denom(x) * denom(x))
```

假设有理数表示为两元素 list 则会违反两条 abstraction barrier。

```python
>>> def square_rational_violating_twice(x):
        return [x[0] * x[0], x[1] * x[1]]
```

abstraction barrier 让程序更容易维护和修改。依赖某一特定表示的 function 越少，想要更换该表示时需要做的改动就越少。上面所有 `square_rational` 的实现行为都正确，但只有第一个能经受未来的变化。即使我们改变了有理数的表示，`square_rational` function 也不需要更新。相比之下，只要 selector 或 constructor 的签名发生变化，`square_rational_violating_once` 就必须修改；而只要有理数的实现发生变化，`square_rational_violating_twice` 就需要更新。

## 2.2.4 数据的性质

abstraction barrier 塑造了我们思考数据的方式。有理数的一种有效表示并不局限于任何特定的实现（例如两元素 list）；它是 `rational` 返回的、可以传给 `numer` 和 `denom` 的值。此外，constructor 和 selector 之间还必须满足恰当的关系。也就是说，如果我们用整数 `n` 和 `d` 构造有理数 `x`，那么应当有 `numer(x)/denom(x)` 等于 `n/d`。

一般来说，我们可以用一组 selector 和 constructor，再加上一些行为条件，来表达抽象数据。只要满足这些行为条件（例如上面的除法性质），这些 selector 和 constructor 就构成某类数据的一种有效表示。abstraction barrier 之下的实现细节可以变化，但只要行为不变，data abstraction 就依然有效，任何用这个 data abstraction 写成的程序也依然正确。

这一观点可以广泛运用，包括我们用来实现有理数的 pair 值。我们其实从未对 pair 究竟是什么说过多少，只说过语言提供了创建和操作两元素 list 的手段。实现一个 pair 所需的行为就是：它把两个值粘合在一起。用行为条件来陈述就是，

- 如果 pair `p` 是由值 `x` 和 `y` 构造的，那么 `select(p, 0)` 返回 `x`，而 `select(p, 1)` 返回 `y`。

我们其实并不需要 `list` 类型来创建 pair。相反，我们可以实现两个 function `pair` 和 `select`，它们与两元素 list 一样能满足这一描述。

```python
>>> def pair(x, y):
        """Return a function that represents a pair."""
        def get(index):
            if index == 0:
                return x
            elif index == 1:
                return y
        return get
```

```python
>>> def select(p, i):
        """Return the element at index i of pair p."""
        return p(i)
```

有了这个实现，我们就可以创建和操作 pair 了。

```python
>>> p = pair(20, 14)
>>> select(p, 0)
20
>>> select(p, 1)
14
```

这种对 higher-order function 的使用，与我们对数据应该是什么的直觉概念毫无相似之处。尽管如此，这些 function 已经足以在程序中表示 pair 了。Function 足以表示 compound data。

展示 pair 的 functional representation，重点不在于 Python 实际上就是这样工作的（出于效率的考虑，list 的实现要直接得多），而在于它本来可以这样工作。functional representation 虽然晦涩，却完全足以表示 pair，因为它满足 pair 需要满足的唯一条件。data abstraction 的实践让我们能够轻松地在各种表示之间切换。

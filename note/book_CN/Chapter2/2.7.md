# 2.7 Object Abstraction

Object 系统让程序员能够高效地构建和使用抽象数据表示。它的设计还允许抽象数据的多种表示共存于同一个程序中。

Object abstraction 的一个核心概念是 *generic function*，也就是能够接受多种不同类型的值的 function。我们将考虑三种实现 generic function 的不同技术：共享 interface、type dispatching 和 type coercion。在逐步建立这些概念的过程中，我们还会发现 Python object 系统中支持创建 generic function 的一些特性。

## 2.7.1 String 转换

为了有效地表示数据，一个 object 值的行为应当像它所要表示的那类数据，包括产生自身的 string 表示。在 Python 这样的交互式语言中，数据值的 string 表示尤为重要，因为 Python 会在交互式会话中自动显示 expression 的值的 string 表示。

String 值是人类之间传递信息的一种基本媒介。字符组成的 sequence 可以显示在屏幕上、打印到纸上、朗读出来、转换成盲文，或者用摩尔斯电码发送。String 对编程也很基础，因为它们可以表示 Python 的 expression。

Python 规定所有 object 都应产生两种不同的 string 表示：一种是人类可解释的文本，另一种是 Python 可解释的 expression。String 的 constructor function `str` 返回人类可读的 string。在可能的情况下，`repr` function 返回一个求值得到相等 object 的 Python expression。*repr* 的 docstring 解释了这一性质：

```

repr(object) -> string

Return the canonical string representation of the object.
For most object types, eval(repr(object)) == object.
```

对一个 expression 的值调用 `repr` 所得到的结果，就是 Python 在交互式会话中打印出来的东西。

```python
>>> 12e12
12000000000000.0
>>> print(repr(12e12))
12000000000000.0
```

如果不存在能求值得到原值的表示，Python 通常会给出一个用尖括号括起来的描述。

```python
>>> repr(min)
'<built-in function min>'
```

`str` constructor 常常与 `repr` 一致，但在某些情况下会给出更易解释的文本表示。例如，对 date 来说，`str` 和 `repr` 就有差别。

```python
>>> from datetime import date
>>> tues = date(2011, 9, 12)
>>> repr(tues)
'datetime.date(2011, 9, 12)'
>>> str(tues)
'2011-09-12'
```

定义 `repr` function 带来一个新的挑战：我们希望它能正确地作用于所有数据类型，甚至是 `repr` 实现时还不存在的数据类型。我们希望它是一个 generic 的、或者说是 *polymorphic function*，即可以作用于许多（*poly*）不同形式（*morph*）的数据的 function。

Object 系统在这种情况下提供了一个优雅的解决方案：`repr` function 总是调用其 argument 上一个名为 `__repr__` 的 method。

```python
>>> tues.__repr__()
'datetime.date(2011, 9, 12)'
```

通过在用户自定义的 class 中实现同一个 method，我们可以把 `repr` 的适用范围扩展到我们将来创建的任何 class。这个例子凸显了 dot expression 的另一个一般性好处：它们提供了一种机制，把已有 function 的作用范围扩展到新的 object 类型。

`str` constructor 的实现方式类似：它调用其 argument 上一个名为 `__str__` 的 method。

```python
>>> tues.__str__()
'2011-09-12'
```

这些 polymorphic function 体现了一条更一般的原则：某些 function 应当能作用于多种数据类型。此外，创建这类 function 的一种办法是使用一个共享的 attribute 名字，但在每个 class 中给出不同的定义。

## 2.7.2 特殊 Methods

在 Python 中，某些 *special names* 会在特殊情形下由 Python interpreter 调用。例如，每当构造一个 object 时，class 的 `__init__` method 都会被自动调用。打印时会自动调用 `__str__` method，而在交互式会话中显示值时会调用 `__repr__`。

Python 中还有许多其他行为也有对应的 special name。下面介绍其中一些最常用的。

**真值和假值。** 我们此前看到，Python 中的数字有真值；更具体地说，0 是假值，其他所有数字都是真值。事实上，Python 中所有 object 都有真值。默认情况下，用户自定义 class 的 object 被认为是真值，但可以用特殊的 `__bool__` method 覆盖这一行为。如果一个 object 定义了 `__bool__` method，那么 Python 就调用该 method 来确定它的真值。

举个例子，假设我们希望余额为 0 的银行账户为假值。我们可以给 `Account` class 添加一个 `__bool__` method 来实现这一行为。

```python
>>> Account.__bool__ = lambda self: self.balance != 0
```

我们可以调用 `bool` constructor 查看一个 object 的真值，也可以在布尔上下文中使用任何 object。

```python
>>> bool(Account('Jack'))
False
>>> if not Account('Jack'):
        print('Jack has nothing')
Jack has nothing
```

**Sequence 操作。** 我们见过，可以调用 `len` function 来确定一个 sequence 的长度。

```python
>>> len('Go Bears!')
9
```

`len` function 会调用其 argument 的 `__len__` method 来确定长度。所有内置 sequence 类型都实现了这个 method。

```python
>>> 'Go Bears!'.__len__()
9
```

如果一个 sequence 没有提供 `__bool__` method，Python 就用它的长度来确定真值。空 sequence 为假值，非空 sequence 为真值。

```python
>>> bool('')
False
>>> bool([])
False
>>> bool('Go Bears!')
True
```

`__getitem__` method 由 element 选择 operator 调用，但也可以直接调用。

```python
>>> 'Go Bears!'[3]
'B'
>>> 'Go Bears!'.__getitem__(3)
'B'
```

**Callable objects。** 在 Python 中，function 是一等的 object，因此它们可以像数据一样到处传递，也可以像其他任何 object 一样拥有 attribute。Python 还允许我们定义能够像 function 那样被“调用”的 object，办法是包含一个 `__call__` method。有了这个 method，我们就能定义一个行为像 higher-order function 的 class。

举个例子，考虑下面这个 higher-order function，它返回一个把常量加到其 argument 上的 function。

```python
>>> def make_adder(n):
        def adder(k):
            return n + k
        return adder
```

```python
>>> add_three = make_adder(3)
>>> add_three(4)
7
```

我们可以创建一个 `Adder` class，定义 `__call__` method 来提供同样的功能。

```python
>>> class Adder(object):
        def __init__(self, n):
            self.n = n
        def __call__(self, k):
            return self.n + k
```

```python
>>> add_three_obj = Adder(3)
>>> add_three_obj(4)
7
```

这里，`Adder` class 的行为像 `make_adder` 这个 higher-order function，而 `add_three_obj` object 的行为像 `add_three` function。我们进一步模糊了数据与 function 之间的界限。

**算术运算。** Special method 还可以定义内置 operator 作用于用户自定义 object 时的行为。为了提供这种通用性，Python 按照特定的协议来施加每个 operator。例如，要求值包含 `+` operator 的 expression，Python 会检查该 expression 左右两个 operand 上的 special method。首先，Python 检查左 operand 的值上有没有 `__add__` method，然后检查右 operand 的值上有没有 `__radd__` method。只要找到其中一个，就用另一个 operand 的值作为 argument 调用该 method。下面几节给出了一些例子。想了解进一步细节的读者，可以参阅 Python 文档中详尽列出的 [operator 的 method 名称](http://docs.python.org/py3k/reference/datamodel.html#special-method-names)。Dive into Python 3 有一章 [special method 名称](http://getpython3.com/diveintopython3/special-method-names.html)，介绍了其中许多 special method 名字的用法。

## 2.7.3 多重表示

Abstraction barrier 让我们能够把数据的使用与数据的表示分离开。然而在大型程序中，谈论某个数据类型“底层的表示”并不总是有意义。其一，一个数据 object 可能有不止一种有用的表示，而我们可能想要设计能够处理多种表示的系统。

举个简单的例子，复数可以用两种几乎等价的方式表示：直角坐标形式（实部和虚部）和极坐标形式（模和角）。有时直角坐标形式更合适，有时极坐标形式更合适。事实上，完全可以设想这样一个系统：复数同时用这两种方式表示，而操作复数的 function 对两种表示都能工作。下面我们就来实现这样一个系统。顺带一提，我们开发这个对复数做算术运算的系统，只是把它当作一个使用 generic operation 的简单但并不现实的程序示例。[复数类型](http://docs.python.org/py3k/library/stdtypes.html#typesnumeric)其实已经内置于 Python，但在这个例子中我们要实现自己的版本。

允许数据有多种表示的想法经常出现。大型软件系统常常是由许多人在很长的时间跨度里设计的，并且还要应对随时间变化的需求。在这样的环境里，根本不可能让所有人事先就数据表示的选择达成一致。除了把表示与使用隔离开的 data abstraction barrier 之外，我们还需要一些 abstraction barrier，把不同的设计选择彼此隔离开来，并让不同的选择能共存于同一个程序中。

我们将从最高层的 abstraction 开始实现，逐步走向具体的表示。一个 `Complex` 数是一个 `Number`，而数可以彼此相加或相乘。数如何相加或相乘，由 method 名字 `add` 和 `mul` 抽象出来。

```python
>>> class Number:
        def __add__(self, other):
            return self.add(other)
        def __mul__(self, other):
            return self.mul(other)
```

这个 class 要求 Number object 拥有 `add` 和 `mul` method，但并没有定义它们。此外，它也没有 `__init__` method。`Number` 的用途并不是被直接实例化，而是作为各种具体数 class 的 superclass。我们的下一个任务是为复数恰当地定义 `add` 和 `mul`。

复数可以看作二维空间中的一个点，这个空间有两个正交的轴：实轴和虚轴。从这个角度看，复数 `c = real + imag * i`（其中 `i * i = -1`）可以看作平面上的一个点，它的水平坐标是 `real`，垂直坐标是 `imag`。复数的加法就是把各自的 `real` 坐标和 `imag` 坐标相加。

在复数相乘时，用极坐标形式把复数表示为 `magnitude` 和 `angle` 会更自然。两个复数的乘积是这样得到的向量：把一个复数按另一个复数的长度拉伸，再把它旋转另一个复数的角度。

`Complex` class 继承自 `Number`，它描述了复数的算术运算。

```python
>>> class Complex(Number):
        def add(self, other):
            return ComplexRI(self.real + other.real, self.imag + other.imag)
        def mul(self, other):
            magnitude = self.magnitude * other.magnitude
            return ComplexMA(magnitude, self.angle + other.angle)
```

这个实现假定已经存在两个用于复数的 class，它们对应复数的两种自然表示：

- `ComplexRI` 由实部和虚部构造复数。
- `ComplexMA` 由模和角构造复数。

**Interfaces。** Object attribute 是 message passing 的一种形式，它让不同的数据类型能以不同方式响应同一条消息。一组共享的消息能在不同 class 中引出相似的行为，这是一种强大的 abstraction 手段。*interface* 是一组共享的 attribute 名字，外加对它们行为的规范说明。就复数而言，实现算术运算所需的 interface 由四个 attribute 组成：`real`、`imag`、`magnitude` 和 `angle`。

要让复数的算术运算正确，这些 attribute 必须保持一致。也就是说，直角坐标 `(real, imag)` 和极坐标 `(magnitude, angle)` 必须描述复平面上的同一个点。`Complex` class 通过确定这些 attribute 如何被用来 `add` 和 `mul` 复数，隐含地定义了这个 interface。

**Properties。** 要求两个或多个 attribute 值彼此保持固定关系，这是一个新问题。一种解决方案是只存储一种表示的 attribute 值，并在需要时计算另一种表示。

Python 有一个简单的特性，可以从零 argument 的 function 即时计算出 attribute。`@property` decorator 让 function 无需 call expression 语法（跟在 expression 后面的圆括号）就能被调用。`ComplexRI` class 存储 `real` 和 `imag` attribute，并在需要时计算 `magnitude` 和 `angle`。

```python
>>> from math import atan2
>>> class ComplexRI(Complex):
        def __init__(self, real, imag):
            self.real = real
            self.imag = imag
        @property
        def magnitude(self):
            return (self.real ** 2 + self.imag ** 2) ** 0.5
        @property
        def angle(self):
            return atan2(self.imag, self.real)
        def __repr__(self):
            return 'ComplexRI({0:g}, {1:g})'.format(self.real, self.imag)
```

由于这样的实现，复数算术所需的全部四个 attribute 都可以不用任何 call expression 就访问到，而对 `real` 或 `imag` 的修改会反映到 `magnitude` 和 `angle` 上。

```python
>>> ri = ComplexRI(5, 12)
>>> ri.real
5
>>> ri.magnitude
13.0
>>> ri.real = 9
>>> ri.real
9
>>> ri.magnitude
15.0
```

类似地，`ComplexMA` class 存储 `magnitude` 和 `angle`，但在查找 `real` 和 `imag` 这两个 attribute 时计算它们。

```python
>>> from math import sin, cos, pi
>>> class ComplexMA(Complex):
        def __init__(self, magnitude, angle):
            self.magnitude = magnitude
            self.angle = angle
        @property
        def real(self):
            return self.magnitude * cos(self.angle)
        @property
        def imag(self):
            return self.magnitude * sin(self.angle)
        def __repr__(self):
            return 'ComplexMA({0:g}, {1:g} * pi)'.format(self.magnitude, self.angle/pi)
```

对模或角的修改会立即反映到 `real` 和 `imag` attribute 上。

```python
>>> ma = ComplexMA(2, pi/2)
>>> ma.imag
2.0
>>> ma.angle = pi
>>> ma.real
-2.0
```

我们对复数的实现现在完成了。实现复数的任一个 class 都可以用作 `Complex` 中任一个算术 function 的任一个 argument。

```python
>>> from math import pi
>>> ComplexRI(1, 2) + ComplexMA(2, pi/2)
ComplexRI(1, 4)
>>> ComplexRI(0, 1) * ComplexRI(0, 1)
ComplexMA(1, 1 * pi)
```

用 interface 来编码多种表示的这种做法有一些吸引人的性质。每种表示的 class 都可以单独开发；它们只需在共享 attribute 的名字以及这些 attribute 的任何行为条件上达成一致。Interface 还是 *additive* 的。如果另一位程序员想往同一个程序里加入复数的第三种表示，他只需再创建一个具有相同 attribute 的 class。

数据的多种表示与本章开头讲到的 data abstraction 思想密切相关。借助 data abstraction，我们能够在不改变程序含义的情况下改变数据类型的实现。借助 interface 和 message passing，我们可以在同一个程序中拥有多种不同的表示。在这两种情况下，都是通过一组名字以及相应的行为条件来定义那使这种灵活性成为可能的 abstraction。

## 2.7.4 Generic Functions

Generic function 是能作用于不同类型 argument 的 method 或 function。我们已经见过很多例子。`Complex.add` method 就是 generic 的，因为它的 `other` 既可以取 `ComplexRI` 也可以取 `ComplexMA` 作为值。这种灵活性是通过确保 `ComplexRI` 和 `ComplexMA` 共享同一个 interface 而获得的。使用 interface 和 message passing 只是实现 generic function 的若干方法之一。本节我们还会考虑另外两种：type dispatching 和 type coercion。

假设除了复数 class 之外，我们还实现一个 `Rational` class 来精确地表示分数。它的 `add` 和 `mul` method 表达的计算与本章前面 `add_rational` 和 `mul_rational` function 相同。

```python
>>> from fractions import gcd
>>> class Rational(Number):
        def __init__(self, numer, denom):
            g = gcd(numer, denom)
            self.numer = numer // g
            self.denom = denom // g
        def __repr__(self):
            return 'Rational({0}, {1})'.format(self.numer, self.denom)
        def add(self, other):
            nx, dx = self.numer, self.denom
            ny, dy = other.numer, other.denom
            return Rational(nx * dy + ny * dx, dx * dy)
        def mul(self, other):
            numer = self.numer * other.numer
            denom = self.denom * other.denom
            return Rational(numer, denom)
```

我们通过包含 `add` 和 `mul` method，实现了 `Number` superclass 的 interface。因此，我们可以用熟悉的 operator 对有理数做加法和乘法。

```python
>>> Rational(2, 5) + Rational(1, 10)
Rational(1, 2)
>>> Rational(1, 4) * Rational(2, 3)
Rational(1, 6)
```

然而，我们还不能把一个有理数加到一个复数上，尽管在数学上这样的组合是明确定义的。我们希望以某种小心控制的方式引入这种跨类型操作，从而在支持它的同时不至于严重违反我们的 abstraction barrier。我们期望的结果之间存在张力：我们既希望能把一个复数加到一个有理数上，又希望用一个 generic 的 `__add__` method 来做到这一点，对所有数值类型都做正确的事。同时，我们又希望尽可能把复数与有理数这两件事分离开，以保持程序的模块化。

**Type dispatching。** 实现跨类型操作的一种办法，是根据 function 或 method 各 argument 的类型来选择行为。Type dispatching 的思路是编写这样的 function：检查收到的 argument 的类型，然后执行适合这些类型的代码。

内置 function `isinstance` 接受一个 object 和一个 class。如果该 object 的 class 就是给定的 class 或者继承自它，就返回真值。

```python
>>> c = ComplexRI(1, 1)
>>> isinstance(c, ComplexRI)
True
>>> isinstance(c, Complex)
True
>>> isinstance(c, ComplexMA)
False
```

Type dispatching 的一个简单例子是 `is_real` function，它对每种复数类型使用不同的实现。

```python
>>> def is_real(c):
        """Return whether c is a real number with no imaginary part."""
        if isinstance(c, ComplexRI):
            return c.imag == 0
        elif isinstance(c, ComplexMA):
            return c.angle % pi == 0
```

```python
>>> is_real(ComplexRI(1, 1))
False
>>> is_real(ComplexMA(2, pi))
True
```

Type dispatching 并不总是用 `isinstance` 来完成。对于算术运算，我们会给 `Rational` 和 `Complex` 的 instance 一个值为 string 的 `type_tag` attribute。当两个值 `x` 和 `y` 有相同的 `type_tag` 时，我们就可以直接用 `x.add(y)` 把它们组合起来。否则，我们就需要一次跨类型操作。

```python
>>> Rational.type_tag = 'rat'
>>> Complex.type_tag = 'com'
>>> Rational(2, 5).type_tag == Rational(1, 2).type_tag
True
>>> ComplexRI(1, 1).type_tag == ComplexMA(2, pi/2).type_tag
True
>>> Rational(2, 5).type_tag == ComplexRI(1, 1).type_tag
False
```

为了组合复数和有理数，我们编写同时依赖两者表示的 function。下面，我们利用这样一个事实：一个 `Rational` 可以近似地转换成一个实数的 `float` 值。这个结果可以与复数组合。

```python
>>> def add_complex_and_rational(c, r):
        return ComplexRI(c.real + r.numer/r.denom, c.imag)
```

乘法涉及类似的转换。在极坐标形式下，复平面上的一个实数总是具有正的模。角 0 表示正数。角 `pi` 表示负数。

```python
>>> def mul_complex_and_rational(c, r):
        r_magnitude, r_angle = r.numer/r.denom, 0
        if r_magnitude < 0:
            r_magnitude, r_angle = -r_magnitude, pi
        return ComplexMA(c.magnitude * r_magnitude, c.angle + r_angle)
```

加法和乘法都满足交换律，所以交换 argument 顺序时可以复用这些跨类型操作的同一份实现。

```python
>>> def add_rational_and_complex(r, c):
        return add_complex_and_rational(c, r)
```

```python
>>> def mul_rational_and_complex(r, c):
        return mul_complex_and_rational(c, r)
```

Type dispatching 的作用是确保这些跨类型操作在恰当的时候被使用。下面，我们重写 `Number` superclass，让它的 `__add__` 和 `__mul__` method 使用 type dispatching。

我们用 `type_tag` attribute 来区分 argument 的类型。也可以直接使用内置的 `isinstance` method，但 tag 让实现更简单。使用 type tag 也说明 type dispatching 未必与 Python object 系统绑定，而是一种在异构领域上创建 generic function 的一般技术。

`__add__` method 考虑两种情况。首先，如果两个 argument 有相同的 type tag，它就假定第一个的 `add` method 可以接受第二个作为 argument。否则，它检查名为 `adders` 的、存放跨类型实现的 dictionary 中是否含有一个能相加这两种 type tag 的 argument 的 function。如果有这样一个 function，`cross_apply` method 会找到并施加它。`__mul__` method 结构类似。

```python
>>> class Number:
        def __add__(self, other):
            if self.type_tag == other.type_tag:
                return self.add(other)
            elif (self.type_tag, other.type_tag) in self.adders:
                return self.cross_apply(other, self.adders)
        def __mul__(self, other):
            if self.type_tag == other.type_tag:
                return self.mul(other)
            elif (self.type_tag, other.type_tag) in self.multipliers:
                return self.cross_apply(other, self.multipliers)
        def cross_apply(self, other, cross_fns):
            cross_fn = cross_fns[(self.type_tag, other.type_tag)]
            return cross_fn(self, other)
        adders = {("com", "rat"): add_complex_and_rational,
                  ("rat", "com"): add_rational_and_complex}
        multipliers = {("com", "rat"): mul_complex_and_rational,
                       ("rat", "com"): mul_rational_and_complex}
```

在 `Number` class 的这个新定义中，所有跨类型实现都以 type tag 对为索引，存放在 `adders` 和 `multipliers` 这两个 dictionary 中。

这种基于 dictionary 的 type dispatching 方法具有可扩展性。`Number` 的新 subclass 可以通过声明一个 type tag，并把跨类型操作加入 `Number.adders` 和 `Number.multipliers`，从而把自己安装进这个系统。它们也可以在 subclass 中定义自己的 `adders` 和 `multipliers`。

虽然我们给系统引入了一些复杂性，但现在我们可以在加法和乘法 expression 中混用各种类型了。

```python
>>> ComplexRI(1.5, 0) + Rational(3, 2)
ComplexRI(3, 0)
>>> Rational(-1, 2) * ComplexMA(4, pi/2)
ComplexMA(2, 1.5 * pi)
```

**Coercion。** 在完全无关的操作作用于完全无关的类型的普遍情形下，尽管实现显式的跨类型操作很繁琐，但这已经是人们所能期望的最好办法了。幸运的是，有时我们可以做得更好：利用类型系统中可能潜藏着的额外结构。不同数据类型往往并非完全独立，可能存在一些办法，把一种类型的 object 看作另一种类型的 object。这个过程称为 *coercion*。例如，如果要求我们把一个有理数与一个复数做算术组合，我们可以把这个有理数看成一个虚部为零的复数。这样做之后，我们就可以用 `Complex.add` 和 `Complex.mul` 把它们组合起来。

一般来说，我们可以通过设计 coercion function 来实现这个想法，它把一种类型的 object 转换成另一种类型的等价 object。下面是一个典型的 coercion function，它把有理数转换成虚部为零的复数：

```python
>>> def rational_to_complex(r):
        return ComplexRI(r.numer/r.denom, 0)
```

`Number` class 的另一种定义通过尝试把两个 argument 转换到同一个类型来执行跨类型操作。`coercions` dictionary 以 type tag 对为索引记录所有可能的 coercion，表示对应的值把第一种类型的值转换成第二种类型的值。

一般来说，无法把每种类型的任意数据 object 都转换成所有其他类型。例如，没有办法把任意复数转换成有理数，因此 `coercions` dictionary 中不会有这样的转换实现。

`coerce` method 返回两个具有相同 type tag 的值。它检查自己 argument 的 type tag，把它们与 `coercions` dictionary 中的条目作比较，并用 `coerce_to` 把其中一个 argument 转换成另一个的类型。要完成我们的跨类型算术系统，`coercions` 中只需要一个条目，它取代了 type-dispatching 版本的 `Number` 中的四个跨类型 function。

```python
>>> class Number:
        def __add__(self, other):
            x, y = self.coerce(other)
            return x.add(y)
        def __mul__(self, other):
            x, y = self.coerce(other)
            return x.mul(y)
        def coerce(self, other):
            if self.type_tag == other.type_tag:
                return self, other
            elif (self.type_tag, other.type_tag) in self.coercions:
                return (self.coerce_to(other.type_tag), other)
            elif (other.type_tag, self.type_tag) in self.coercions:
                return (self, other.coerce_to(self.type_tag))
        def coerce_to(self, other_tag):
            coercion_fn = self.coercions[(self.type_tag, other_tag)]
            return coercion_fn(self)
        coercions = {('rat', 'com'): rational_to_complex}
```

与定义显式跨类型操作的方法相比，这种 coercion 方案有一些优点。虽然我们仍然需要编写 coercion function 来关联各种类型，但每对类型只需写一个 function，而不必为每组类型与每个 generic 操作都写不同的 function。我们在这里依赖的事实是：类型之间恰当的变换只取决于类型本身，而不取决于要施加的具体操作。

更进一步的优势来自对 coercion 的扩展。有些更精巧的 coercion 方案不只是一味地把一种类型转换成另一种类型，而是可能尝试把两种不同的类型各自转换成第三种公共类型。设想一个菱形和一个矩形：两者都不是对方的特例，但两者都可以看作四边形。Coercion 的另一个扩展是迭代式的 coercion，即借助中间类型把一种数据类型转换成另一种。设想一个整数可以先转换成有理数、再把这个有理数转换成实数，从而转换成实数。以这种方式把 coercion 串接起来，可以减少程序所需的 coercion function 总数。

尽管有这些优点，coercion 确实也有潜在的缺点。其一，coercion function 在施加时可能丢失信息。在我们的例子里，有理数是精确的表示，但转换成复数后就变成了近似值。

有些编程语言内置了自动 coercion 系统。事实上，早期版本的 Python 在 object 上有一个 `__coerce__` special method。最终，内置 coercion 系统的复杂性不足以证明它的用处，于是它被移除了。取而代之的是，具体的 operator 按需对其 argument 施加 coercion。

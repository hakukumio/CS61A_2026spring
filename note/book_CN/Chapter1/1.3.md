# 1.3 定义新的 Functions

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=j3uTRrPBrKk)

我们已经识别出 Python 中一些任何强大的编程语言都必须具备的要素：

1. 数字和算术运算属于 *primitive* 的内置数据值和 function。
2. 嵌套的 function application 提供了*组合*运算的手段。
3. 把名字绑定到值提供了有限的一种*abstraction* 手段。

现在我们将来学习 *function definition*，这是一种强大得多的 abstraction 技术：借助它，一个名字可以被绑定到复合运算上，而这个复合运算随后可以作为一个单元被引用。

我们先来考察如何表达*平方*这一概念。我们可以说：“要平方一个东西，就把它与自身相乘。”在 Python 中这样表达：

```python
>>> def square(x):
        return mul(x, x)
```

这就定义了一个新 function，它被赋予名字 `square`。这个用户自定义的 function 并不是 interpreter 内置的。它表示把某个东西与自身相乘这一复合运算。这个定义中的 `x` 称为 *formal parameter*，它为待相乘的那个东西提供了一个名字。这个 definition 创建了这个用户自定义的 function，并把它与名字 `square` 关联起来。

**如何定义一个 function。** Function definition 由以下部分构成：一条 `def` statement，它指明一个 `<name>` 和一个以逗号分隔的具名 `<formal parameters>` 列表；接着是一条 `return` statement，称为 function body，它指明该 function 的 `<return expression>`——也就是每当该 function 被应用时都要 evaluate 的那个 expression：

```

def <name>(<formal parameters>):
    return <return expression>
```

第二行*必须*缩进——大多数程序员用四个空格来缩进。Return expression 不会立即被 evaluate；它作为新定义的 function 的一部分被存储起来，只有在该 function 最终被应用时才被 evaluate。

定义了 `square` 之后，我们就可以用一个 call expression 来应用它：

```python
>>> square(21)
441
>>> square(add(2, 5))
49
>>> square(square(3))
81
```

我们也可以把 `square` 当作积木，用来定义其他 function。例如，我们可以轻松定义一个 function `sum_squares`，它接受任意两个数字作为 argument，返回它们平方的和：

```python
>>> def sum_squares(x, y):
        return add(square(x), square(y))
```

```python
>>> sum_squares(3, 4)
25
```

用户自定义的 function 与内置 function 的用法完全相同。事实上，单看 `sum_squares` 的 definition，你根本无法判断 `square` 是 interpreter 内置的、从 module 导入的，还是用户自定义的。

`def` statement 和 assignment statement 都会把名字绑定到值上，并且原有的 binding 会丢失。例如，下面的 `g` 先是一个不接受 argument 的 function，然后是一个数字，最后又是一个接受两个 argument 的不同 function。

```python
>>> def g():
        return 1
>>> g()
1
>>> g = 2
>>> g
2
>>> def g(h, i):
        return h + i
>>> g(1, 2)
3
```

## 1.3.1 Environments

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=gyk0Qutui1s)

我们的 Python 子集现在已经复杂到程序的含义不再显而易见的程度。如果一个 formal parameter 与某个内置 function 同名，会怎么样？两个 function 能共用名字而不引起混乱吗？要解答这类问题，我们必须更详细地描述 environment。

一个 expression 在其中被 evaluate 的 environment 由一系列 *frame* 构成，它们被画成方框。每个 frame 包含若干 *binding*，每个 binding 把名字与对应的值关联起来。有且仅有一个 *global* frame。Assignment statement 和 import statement 会向当前 environment 的第一个 frame 添加条目。到目前为止，我们的 environment 只包含 global frame。

```python

from math import pi
tau = 2 * pi
```

这幅 *environment diagram* 展示了当前 environment 的 binding，以及名字所绑定到的值。本书中的 environment diagram 是交互式的：你可以单步执行左边小程序中的各行，观察右边的 environment 状态如何演变。你也可以点击 “Edit code in Online Python Tutor” 链接，把这个示例载入 [Online Python Tutor](http://composingprograms.com/tutor.html)——这是 [Philip Guo](http://www.pgbovine.net/) 创建的一个工具，用来生成这些 environment diagram。我们鼓励你自己创建示例，并研究由此得到的 environment diagram。

Function 也会出现在 environment diagram 中。一条 `import` statement 把名字绑定到一个内置 function 上。一条 `def` statement 把名字绑定到由该 definition 创建的用户自定义 function 上。导入 `mul` 并定义 `square` 之后得到的 environment 如下所示：

```python

from operator import mul
def square(x):
    return mul(x, x)
```

每个 function 都画成一行，以 `func` 开头，后面跟着 function 名字和 formal parameter。像 `mul` 这样的内置 function 没有 formal parameter 名字，因此总是改用 `...`。

Function 的名字会出现两次：一次在 frame 中，一次作为 function 自身的一部分。出现在 function 中的那个名字称为 *intrinsic name*。frame 中的那个名字则是 *bound name*。两者之间存在差异：不同的名字可以指向同一个 function，但那个 function 自身只有一个 intrinsic name。

在 frame 中绑定到某个 function 的名字，才是 evaluation 期间使用的名字。Function 的 intrinsic name 在 evaluation 中不起作用。用 *Forward* 按钮单步执行下面的示例，你会看到：一旦名字 `max` 被绑定到值 3，它就不能再被当作 function 使用了。

```python

f = max
max = 3
result = f(2, 3, 4)
max(1, 2)  # Causes an error
```

错误信息 `TypeError: 'int' object is not callable` 报告的是：名字 `max`（当前绑定到数字 3）是一个整数而不是 function。因此，它不能用作 call expression 中的 operator。

**Function Signature。** 不同的 function 允许接受的 argument 个数不同。为了记录这些要求，我们绘制每个 function 时都会显示 function 名字及其 formal parameter。用户自定义的 function `square` 只接受 `x`；提供更多或更少的 argument 都会导致错误。对一个 function 的 formal parameter 的描述称为该 function 的 signature。

Function `max` 可以接受任意数量的 argument。它被画成 `max(...)`。无论接受多少个 argument，所有内置 function 都会被渲染成 `<name>(...)`，因为这些 primitive function 从未被显式定义过。

## 1.3.2 调用用户自定义的 Functions

要 evaluate 一个 operator 指向用户自定义 function 的 call expression，Python interpreter 会遵循一个计算过程。与任何 call expression 一样，interpreter 会 evaluate operator 和 operand expression，然后把所指名的 function 应用到由此得到的 argument 上。

应用一个用户自定义的 function 会引入第二个 *local* frame，它只对该 function 可见。要把一个用户自定义的 function 应用到若干 argument 上：

1. 在一个新的 *local* frame 中，把 argument 绑定到该 function 的 formal parameter 名字上。
2. 在以这个 frame 为起点的 environment 中执行该 function 的 body。

body 在其中被 evaluate 的 environment 由两个 frame 构成：首先是包含 formal parameter binding 的 local frame，然后是包含其余一切内容的 global frame。每一次 function application 都有自己独立的 local frame。

为了详细说明一个例子，下面描绘了同一个示例的 environment diagram 中的若干步骤。执行完第一条 import statement 之后，global frame 中只绑定了名字 `mul`。

```python

from operator import mul
def square(x):
    return mul(x, x)
square(-2)
```

首先，执行 function `square` 的 definition statement。注意，整条 `def` statement 是在一步之内处理完的。function 的 body 要到该 function 被调用时才执行（而不是在被定义时）。

```python

from operator import mul
def square(x):
    return mul(x, x)
square(-2)
```

接下来，用 argument `-2` 调用 `square` function，于是创建了一个新 frame，其中 formal parameter `x` 绑定到值 `-2`。

```python

from operator import mul
def square(x):
    return mul(x, x)
square(-2)
```

然后，在当前 environment（由图中所示的两个 frame 构成）中查找名字 `x`。在两次出现中，`x` 都 evaluate 为 `-2`，因此 `square` function 返回 4。

```python

from operator import mul
def square(x):
    return mul(x, x)
square(-2)
```

`square()` frame 中的 “Return value” 并不是一个名字 binding；它表示的是创建该 frame 的那次 function call 所返回的值。

即使在这个简单的例子中，也用到了两个不同的 environment。顶层 expression `square(-2)` 在 global environment 中 evaluate，而 return expression `mul(x, x)` 则在调用 `square` 所创建的 environment 中 evaluate。`x` 和 `mul` 都绑定在这个 environment 中，但在不同的 frame 里。

environment 中 frame 的顺序会影响在 expression 中查找某个名字所得到的值。我们之前说过，名字 evaluate 为当前 environment 中与该名字关联的值。现在我们可以说得更精确：

**Name Evaluation。** 一个名字 evaluate 为：在当前 environment 中能够找到该名字的最早那个 frame 里，绑定到该名字的值。

我们从 environment、名字和 function 出发构建的概念框架构成了一套 *model of evaluation*；虽然一些机械细节仍未指明（例如 binding 是如何实现的），但我们的模型确实精确而正确地描述了 interpreter 如何 evaluate call expression。在第 3 章中我们将看到，这个模型如何充当实现一门编程语言的可用 interpreter 的蓝图。

## 1.3.3 示例：调用用户自定义的 Function

让我们再次考虑之前那两个简单的 function definition，并说明 evaluate 用户自定义 function 的 call expression 的过程。

```python

from operator import add, mul
def square(x):
    return mul(x, x)

def sum_squares(x, y):
    return add(square(x), square(y))

result = sum_squares(5, 12)
```

Python 首先 evaluate 名字 `sum_squares`，它绑定到 global frame 中一个用户自定义的 function。primitive 数值 expression 5 和 12 evaluate 为它们所表示的数字。

接下来，Python 应用 `sum_squares`，这会引入一个 local frame，把 x 绑定到 5、y 绑定到 12。

```python

from operator import add, mul
def square(x):
    return mul(x, x)

def sum_squares(x, y):
    return add(square(x), square(y))

result = sum_squares(5, 12)
```

`sum_squares` 的 body 中包含这个 call expression：

```

  add     (  square(x)  ,  square(y)  )
________     _________     _________
operator     operand 0     operand 1
```

这三个 subexpression 都在当前 environment 中 evaluate，该 environment 以标有 `sum_squares()` 的 frame 为起点。operator subexpression `add` 是在 global frame 中找到的名字，绑定到用于加法运算的内置 function 上。两个 operand subexpression 必须在应用加法之前依次 evaluate。两个 operand 都在以标有 `sum_squares` 的 frame 为起点的当前 environment 中 evaluate。

在 `operand 0` 中，`square` 指的是 global frame 中一个用户自定义的 function，而 `x` 指的是 local frame 中的数字 5。Python 把 `square` 应用到 5 上，为此又引入一个 local frame，把 x 绑定到 5。

```python

from operator import add, mul
def square(x):
    return mul(x, x)

def sum_squares(x, y):
    return add(square(x), square(y))

result = sum_squares(5, 12)
```

使用这个 environment，expression `mul(x, x)` evaluate 为 25。

我们的 evaluation 过程现在转向 `operand 1`，其中 `y` 指的是数字 12。Python 再次 evaluate `square` 的 body，这次又引入一个 local frame，把 `x` 绑定到 12。因此，`operand 1` evaluate 为 144。

```python

from operator import add, mul
def square(x):
    return mul(x, x)

def sum_squares(x, y):
    return add(square(x), square(y))

result = sum_squares(5, 12)
```

最后，把加法应用到 argument 25 和 144 上，得到 `sum_squares` 最终的 return value：169。

```python

from operator import add, mul
def square(x):
    return mul(x, x)

def sum_squares(x, y):
    return add(square(x), square(y))

result = sum_squares(5, 12)
```

这个例子展示了我们目前为止发展出的许多基本思想。名字被绑定到值上，这些值分布在许多相互独立的 local frame 中，另外还有一个包含共享名字的 global frame。每当一个 function 被调用时，都会引入一个新的 local frame，即使同一个 function 被调用两次也是如此。

这整套机制的存在，是为了确保在程序执行过程中，名字能在正确的时刻解析到正确的值。这个例子说明了我们的模型为什么需要引入这些复杂性。三个 local frame 都包含名字 `x` 的 binding，但这个名字在不同的 frame 中绑定到不同的值。Local frame 使这些名字彼此隔离。

## 1.3.4 局部名字

function 的实现中有一个细节不应该影响该 function 的行为，那就是实现者为该 function 的 formal parameter 选取的名字。因此，下面这些 function 应当表现出相同的行为：

```python
>>> def square(x):
        return mul(x, x)
>>> def square(y):
        return mul(y, y)
```

这一原则——function 的含义应当独立于其作者所选用的 parameter 名字——对编程语言有着重要的影响。最简单的推论是：function 的 parameter 名字必须保持在 function 的 body 局部范围内。

如果 parameter 不是各自 function body 的局部名字，那么 `square` 中的 parameter `x` 就可能与 `sum_squares` 中的 parameter `x` 混淆。关键在于，情况并非如此：不同 local frame 中 `x` 的 binding 彼此无关。这个计算模型经过精心设计，正是为了保证这种独立性。

我们说，一个局部名字的 *scope* 限于定义它的那个用户自定义 function 的 body。当一个名字不再可访问时，它就超出了 scope。这种作用域行为并不是我们模型中的什么新事实；它只是 environment 运作方式的推论。

## 1.3.5 选择名字

名字可以互换并不意味着 formal parameter 的名字完全无关紧要。恰恰相反，精心选取的 function 和 parameter 名字对于人类理解 function definition 至关重要！

以下准则改编自 [Python 代码风格指南](http://www.python.org/dev/peps/pep-0008)，它是所有（不叛逆的）Python 程序员的指南。一套共享的约定能让开发者社区成员之间的交流更顺畅。遵循这些约定的一个 side effect 是，你会发现自己的代码在内部变得更加一致。

1. Function 名字用小写，单词之间用下划线分隔。鼓励使用描述性的名字。
2. Function 名字通常让人联想到 interpreter 施加到 argument 上的操作（例如 `print`、`add`、`square`），或者由此得到的结果量的名字（例如 `max`、`abs`、`sum`）。
3. Parameter 名字用小写，单词之间用下划线分隔。优先使用单个单词的名字。
4. Parameter 名字应当让人联想到该 parameter 在 function 中扮演的角色，而不只是允许的 argument 类型。
5. 当 parameter 的作用显而易见时，单字母的名字是可以接受的，但要避免使用 “l”（小写 ell）、“O”（大写 oh）或 “I”（大写 i），以免与数字混淆。

这些准则有许多例外，即使在 Python 标准库中也是如此。就像英语的词汇一样，Python 从形形色色的贡献者那里继承了各种词，结果并不总是一致。

## 1.3.6 Function 作为 Abstractions

尽管 `sum_squares` 非常简单，它却体现了用户自定义 function 最强大的特性。Function `sum_squares` 是基于 function `square` 定义的，但它只依赖 `square` 在其输入 argument 和输出值之间所定义的关系。

我们编写 `sum_squares` 时，无需关心*如何*平方一个数字。平方是如何计算出来的这些细节可以被隐藏起来，留待以后再考虑。事实上，就 `sum_squares` 而言，`square` 并不是某个特定的 function body，而是对 function 的一种 abstraction，即所谓的 functional abstraction。在这个 abstraction 层次上，任何能计算平方的 function 都一样好。

因此，仅从它们返回的值来看，下面两个用于平方一个数字的 function 应当是无法区分的。它们各自接受一个数值 argument，并产生该数字的平方作为值。

```python
>>> def square(x):
        return mul(x, x)
>>> def square(x):
        return mul(x, x-1) + x
```

换句话说，function definition 应当能够隐藏细节。function 的使用者可能并非编写这个 function 的人，而可能是从另一位程序员那里把它当作一个“黑箱”拿到的。程序员使用一个 function 时，不应该需要知道它是如何实现的。Python 库就具备这一性质。许多开发者使用其中定义的 function，但很少有人去查看它们的实现。

**Functional abstraction 的各个方面。** 要掌握 functional abstraction 的使用，考虑它的三个核心属性往往很有帮助。function 的 *domain* 是它能接受的一组 argument。function 的 *range* 是它能返回的一组值。function 的 *intent* 是它在输入与输出之间计算出的关系（以及它可能产生的任何 side effect）。通过 domain、range 和 intent 来理解 functional abstraction，对于在复杂程序中正确使用它们至关重要。

例如，我们用来实现 `sum_squares` 的任何 `square` function 都应当具备这些属性：

- *domain* 是任意单个实数。
- *range* 是任意非负实数。
- *intent* 是输出为输入的平方。

这些属性并没有规定 intent 是如何实现的；那个细节已经被抽象掉了。

## 1.3.7 Operators

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=gDsdcF1bpBs)

数学 operator（例如 `+` 和 `-`）提供了我们关于组合方法的第一个例子，但我们还没有为包含这些 operator 的 expression 定义 evaluation 过程。

带有中缀 operator 的 Python expression 各自都有自己的 evaluation 过程，但你通常可以把它们看作 call expression 的简写形式。当你看到

```python
>>> 2 + 3
5
```

不妨就把它看作下面这行的简写：

```python
>>> add(2, 3)
5
```

中缀写法可以像 call expression 一样嵌套。Python 应用常规的数学 operator 优先级规则，这些规则决定了如何解读包含多个 operator 的复合 expression。

```python
>>> 2 + 3 * 4 + 5
19
```

它 evaluate 出的结果与下面相同：

```python
>>> add(add(2, mul(3, 4)), 5)
19
```

call expression 中的嵌套比 operator 写法更明确，但也更难读。Python 还允许用圆括号对 subexpression 进行分组，从而覆盖常规的优先级规则，或者让 expression 的嵌套结构更明确。

```python
>>> (2 + 3) * (4 + 5)
45
```

它 evaluate 出的结果与下面相同：

```python
>>> mul(add(2, 3), add(4, 5))
45
```

说到除法，Python 提供了两个中缀 operator：`/` 和 `//`。前者是普通除法，因此即使除数能整除被除数，结果也是 *浮点数*，也就是小数值：

```python
>>> 5 / 4
1.25
>>> 8 / 4
2.0
```

而 `//` operator 则把结果向下取整为整数：

```python
>>> 5 // 4
1
>>> -5 // 4
-2
```

这两个 operator 分别是 `truediv` 和 `floordiv` function 的简写。

```python
>>> from operator import truediv, floordiv
>>> truediv(5, 4)
1.25
>>> floordiv(5, 4)
1
```

在程序中，你可以随意使用中缀 operator 和圆括号。对于简单的数学运算，地道的 Python 更偏爱 operator 而非 call expression。

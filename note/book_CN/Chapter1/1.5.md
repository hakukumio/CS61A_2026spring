# 1.5 控制

到目前为止，我们能定义的 function 的表达能力非常有限，因为我们还没有引入进行比较、并根据比较结果执行不同操作的手段。*Control statement* 将赋予我们这种能力。这类 statement 根据逻辑比较的结果来控制程序执行的流程。

Statement 与我们此前研究过的 expression 有着根本的不同。它们没有值。执行一条 control statement 并不是在计算什么，而是决定 interpreter 接下来应该做什么。

## 1.5.1 Statements

到目前为止，我们主要考虑的是如何对一个 expression 进行 evaluation。不过，我们已经见过三类 statement：assignment、`def` 和 `return` statement。这些 Python 代码行本身并不是 expression，尽管它们都把 expression 作为组成部分包含在内。

Statement 不是被 evaluate 的，而是被*执行*的。每条 statement 都描述了对 interpreter 状态的某种改变，执行一条 statement 就是应用这种改变。正如我们在 `return` 和 assignment statement 中看到的那样，执行 statement 可能涉及对其中包含的 subexpression 进行 evaluation。

Expression 也可以作为 statement 被执行，这时它会被 evaluate，但它的值会被丢弃。执行一个 pure function 不会产生任何 effect，但执行一个非 pure 的 function 则可能由于 function application 而产生 effect。

例如，考虑下面这个例子：

```python
>>> def square(x):
        mul(x, x) # Watch out! This call doesn't return a value.
```

这个例子是合法的 Python，但很可能不是本意。这个 function 的 body 由一个 expression 构成。单独一个 expression 本身就是一条合法的 statement，但这条 statement 的 effect 是：`mul` function 被调用，而结果被丢弃。如果你想利用某个 expression 的结果做点什么，就必须明确表达出来：你可以用 assignment statement 把它存起来，或者用 return statement 把它返回：

```python
>>> def square(x):
        return mul(x, x)
```

有时，当 body 中调用的是 `print` 这类非 pure 的 function 时，让 function 的 body 就是一个 expression 确实是合理的。

```python
>>> def print_square(x):
        print(square(x))
```

从最高层面看，Python interpreter 的工作就是执行由 statement 组成的程序。然而，计算中许多有趣的工作都来自对 expression 的 evaluation。Statement 掌管着程序中不同 expression 之间的关系，以及它们的结果将如何被处理。

## 1.5.2 Compound Statements

一般来说，Python 代码是一个 statement 序列。simple statement 是不以冒号结尾的单行。compound statement 之所以这样称呼，是因为它由其他 statement（simple 的和 compound 的）组成。Compound statement 通常跨越多行，以一个以冒号结尾的单行 header 开始，这个 header 标识了 statement 的类型。一个 header 连同紧跟其后、缩进的 statement suite，合起来称为一个 clause。一个 compound statement 由一个或多个 clause 组成：

```

<header>:
    <statement>
    <statement>
    ...
<separating header>:
    <statement>
    <statement>
    ...
...
```

我们可以用这些概念来理解此前已经介绍过的 statement。

- Expression、return statement 和 assignment statement 都是 simple statement。
- `def` statement 是 compound statement。`def` header 之后的 suite 定义了 function body。

针对每种 header 都有专门的 evaluation 规则，它们规定了该 header 的 suite 中的 statement 何时执行、是否执行。我们说这个 header 控制着它的 suite。例如，对于 `def` statement，我们看到 return expression 并不会立即被 evaluate，而是被存储起来，等到所定义的 function 最终被调用时再使用。

现在我们也能够理解多行程序了。

- 要执行一个 statement 序列，就先执行第一条 statement。如果该 statement 没有重定向控制流，那么就继续执行序列中其余的 statement（如果还有的话）。

这个定义揭示了 recursive 定义的 *sequence* 的本质结构：一个 sequence 可以分解为它的第一个 element 和其余 element。一个 statement 序列的“其余部分”本身又是一个 statement 序列！因此，我们可以 recursive 地应用这条执行规则。这种把 sequence 看作 recursive 数据结构的观点在后面几章中还会再次出现。

这条规则的重要推论是：statement 按顺序执行，但由于控制流被重定向，后面的 statement 可能永远不会被执行到。

**实用建议。** 缩进一个 suite 时，所有行都必须以相同的量、相同的方式缩进（使用空格，而不是制表符）。缩进上任何不一致都会导致错误。

## 1.5.3 定义 Functions II：局部赋值

起初，我们说用户自定义 function 的 body 只包含一条带单个 return expression 的 `return` statement。事实上，function 可以定义一个超出一个 expression 范围的操作序列。

每当一个用户自定义 function 被应用时，其 definition 的 suite 中的 clause 序列就会在一个 local environment 中执行——这个 environment 以调用该 function 所创建的 local frame 为起点。`return` statement 重定向控制流：一旦第一条 `return` statement 被执行，function application 的过程就终止，而 `return` expression 的值就是被应用的 function 的 return value。

Assignment statement 可以出现在 function body 中。例如，下面这个 function 用两步计算返回两个量之差的绝对值占第一个量的百分比：

```python

def percent_difference(x, y):
    difference = abs(x-y)
    return 100 * difference / x
result = percent_difference(40, 50)
```

Assignment statement 的 effect 是把一个名字绑定到当前 environment 的*第一个* frame 中的某个值上。因此，function body 中的 assignment statement 无法影响 global frame。Function 只能操作自己的 local environment，这一事实对于编写 *modular* 的程序至关重要——在这类程序中，pure function 之间只通过它们接受和返回的值进行交互。

当然，`percent_difference` function 也可以写成单个 expression，如下所示，但这样的 return expression 更复杂。

```python
>>> def percent_difference(x, y):
        return 100 * abs(x-y) / x
>>> percent_difference(40, 50)
25.0
```

到目前为止，局部赋值还没有增强我们的 function definition 的表达能力。当它与其他 control statement 结合使用时，就会做到这一点。此外，局部赋值还通过把名字赋给中间量，在厘清复杂 expression 的含义方面发挥着关键作用。

## 1.5.4 Conditional Statements

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=dijoBZH44kU)

Python 有一个计算绝对值的内置 function。

```python
>>> abs(-2)
2
```

我们希望能自己实现这样一个 function，但眼下还没有明显的办法来定义带有比较和选择的 function。我们想表达的是：如果 `x` 为正，`abs(x)` 返回 `x`。此外，如果 `x` 为 0，`abs(x)` 返回 0。否则，`abs(x)` 返回 `-x`。在 Python 中，我们可以用一个 conditional statement 来表达这种选择。

```python

def absolute_value(x):
    """Compute abs(x)."""
    if x > 0:
        return x
    elif x == 0:
        return 0
    else:
        return -x

result = absolute_value(-2)
```

`absolute_value` 的这个实现引出几个重要问题：

**Conditional statement**。Python 中的 conditional statement 由一系列 header 和 suite 组成：一个必需的 `if` clause、一个可选的 `elif` clause 序列，最后是一个可选的 `else` clause：

```

if <expression>:
    <suite>
elif <expression>:
    <suite>
else:
    <suite>
```

执行 conditional statement 时，各个 clause 会按顺序被逐一考虑。执行一个 conditional clause 的计算过程如下。

1. Evaluate header 中的 expression。
2. 如果它是 true value，就执行该 suite。然后跳过 conditional statement 中后续的所有 clause。

如果执行到 `else` clause（只有在所有 `if` 和 `elif` expression 都 evaluate 为 false value 时才会如此），就执行它的 suite。

**Boolean context**。上面，执行过程提到了“false value”和“true value”。conditional block 的 header statement 内部的 expression 被说成处于 *boolean context* 中：它们的真值对控制流有影响，除此之外，它们的值既不会被赋值也不会被返回。Python 中有若干种 false value，包括 0、`None` 以及 *boolean* 值 `False`。其他所有数字都是 true value。在第 2 章中我们会看到，Python 中每一种内置数据类型都既有 true value 也有 false value。

**Boolean value**。Python 有两个 boolean value，分别叫 `True` 和 `False`。Boolean value 表示逻辑 expression 中的真值。内置的比较运算 `>, <, >=, <=, ==, !=` 会返回这些值。

```python
>>> 4 < 2
False
>>> 5 >= 5
True
```

第二个例子读作“5 大于或等于 5”，它对应 `operator` module 中的 function `ge`。

```python
>>> 0 == -0
True
```

最后一个例子读作“0 等于 -0”，它对应 `operator` module 中的 `eq`。注意，Python 把赋值（`=`）与相等比较（`==`）区分开来，这是许多编程语言共有的惯例。

**Boolean operator**。Python 还内置了三个基本的逻辑 operator：

```python
>>> True and False
False
>>> True or False
True
>>> not False
True
```

逻辑 expression 也有相应的 evaluation 过程。这些过程利用了这样一个事实：有时无需 evaluate 一个逻辑 expression 的所有 subexpression 就能确定它的真值，这一特性称为 *short-circuiting*。

要 evaluate expression `<left> and <right>`：

1. Evaluate subexpression `<left>`。
2. 如果结果是 false value `v`，那么这个 expression 就 evaluate 为 `v`。
3. 否则，这个 expression 就 evaluate 为 subexpression `<right>` 的值。

要 evaluate expression `<left> or <right>`：

1. Evaluate subexpression `<left>`。
2. 如果结果是 true value `v`，那么这个 expression 就 evaluate 为 `v`。
3. 否则，这个 expression 就 evaluate 为 subexpression `<right>` 的值。

要 evaluate expression `not <exp>`：

1. Evaluate `<exp>`；如果结果是 false value，其值为 `True`，否则为 `False`。

这些值、规则和 operator 为我们提供了组合比较结果的手段。执行比较并返回 boolean value 的 function 通常以 `is` 开头，后面不跟下划线（例如 `isfinite`、`isdigit`、`isinstance` 等）。

## 1.5.5 迭代

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=x23Rw591l-s)

除了选择执行哪些 statement 之外，control statement 还用来表达重复。如果我们写下的每一行代码都只执行一次，那么编程就会是一项非常没有效率的活动。只有通过反复执行 statement，我们才能释放计算机的全部潜力。我们已经见过一种重复形式：一个 function 可以被应用很多次，尽管它只被定义一次。迭代式的控制结构则是多次执行同一批 statement 的另一种机制。

考虑 Fibonacci 数列，其中每个数都是前两个数之和：

```

0, 1, 1, 2, 3, 5, 8, 13, 21, ...
```

每个值都通过反复应用“前两项相加”这条规则构造出来。第一个和第二个固定为 0 和 1。例如，第八个 Fibonacci 数是 13。

我们可以用 `while` statement 来枚举 `n` 个 Fibonacci 数。我们需要跟踪已经创建了多少个值（`k`），以及第 k 个值（`curr`）和它的前一个值（`pred`）。单步执行这个 function，观察 Fibonacci 数是如何逐个演变、并绑定到 `curr` 上的。

```python

def fib(n):
    """Compute the nth Fibonacci number, for n >= 2."""
    pred, curr = 0, 1   # Fibonacci numbers 1 and 2
    k = 2               # Which Fib number is curr?
    while k < n:
        pred, curr = curr, pred + curr
        k = k + 1
    return curr

result = fib(8)
```

记住，在 assignment statement 中，逗号用来分隔多个名字和值。下面这一行：

```

pred, curr = curr, pred + curr
```

的效果是把名字 `pred` 重新绑定到 `curr` 的值，同时把 `curr` 重新绑定到 `pred + curr` 的值。`=` 右侧的所有 expression 都会在任何重新绑定发生之前被 evaluate。

这一事件顺序——在更新左侧的任何 binding 之前，先把 `=` 右侧的一切都 evaluate 完——对这个 function 的正确性至关重要。

一个 `while` clause 包含一个 header expression，后面跟着一个 suite：

```

while <expression>:
    <suite>
```

要执行一个 `while` clause：

1. Evaluate header 中的 expression。
2. 如果它是 true value，就执行该 suite，然后回到第 1 步。

在第 2 步中，`while` clause 的整个 suite 会在 header expression 再次被 evaluate 之前执行完毕。

为了防止 `while` clause 的 suite 被无限期地执行下去，suite 应当在每一轮中都改变某个 binding。

不会终止的 `while` statement 称为 infinite loop。按 `<Control>-C` 可以强制 Python 停止循环。

## 1.5.6 测试

*Testing* 一个 function，就是验证该 function 的行为是否符合预期。我们的 function 语言现在已经足够复杂，我们得开始测试自己的实现了。

一个 *test* 是系统地执行这种验证的机制。Test 通常采取另一个 function 的形式，其中包含一个或多个对被测试 function 的示例 call。然后，把返回的值与预期结果进行核对。大多数 function 都意在通用，而 test 则不然：它涉及挑选并验证使用特定 argument 值的 call。Test 还能起到文档的作用：它们演示了如何调用一个 function，以及哪些 argument 值是合适的。

**Assertion**。程序员使用 `assert` statement 来验证预期，例如被测试 function 的输出。一条 `assert` statement 包含一个处于 boolean context 中的 expression，后面跟一行带引号的文本（单引号和双引号都可以，但要保持一致），如果该 expression evaluate 为 false value，这行文本就会被显示出来。

```python
>>> assert fib(8) == 13, 'The 8th Fibonacci number should be 13'
```

当被断言的 expression evaluate 为 true value 时，执行 assert statement 没有任何 effect。当它为 false value 时，`assert` 会导致一个错误，从而中止执行。

针对 `fib` 的 test function 应当测试若干个 argument，包括 `n` 的极端取值。

```python
>>> def fib_test():
        assert fib(2) == 1, 'The 2nd Fibonacci number should be 1'
        assert fib(3) == 1, 'The 3rd Fibonacci number should be 1'
        assert fib(50) == 7778742049, 'Error at the 50th Fibonacci number'
```

把 Python 写进文件（而不是直接写进 interpreter）时，test 通常写在同一文件中，或者写在后缀为 `_test.py` 的相邻文件中。

**Doctest**。Python 提供了一种便捷的方法，可以把简单的 test 直接放进 function 的 docstring 中。docstring 的第一行应当包含对 function 的一句话描述，后面跟一个空行。之后可以给出对 argument 和行为的详细描述。此外，docstring 还可以包含一段调用该 function 的示例交互会话：

```

>>> def sum_naturals(n):
        """Return the sum of the first n natural numbers.

        >>> sum_naturals(10)
        55
        >>> sum_naturals(100)
        5050
        """
        total, k = 0, 1
        while k <= n:
            total, k = total + k, k + 1
        return total
```

然后，就可以通过 [doctest 模块](http://docs.python.org/py3k/library/doctest.html)来验证这段交互。下面，`globals` function 返回 global environment 的一种表示，interpreter 在对 expression 进行 evaluation 时需要用到它。

```python
>>> from doctest import testmod
>>> testmod()
TestResults(failed=0, attempted=2)
```

如果只想验证单个 function 的 doctest 交互，我们可以使用 `doctest` 中一个名为 `run_docstring_examples` 的 function。遗憾的是，这个 function 调用起来有点复杂。它的第一个 argument 是要测试的 function。第二个 argument 应当始终是 expression `globals()` 的结果，它是一个返回 global environment 的 built-in function。第三个 argument 为 `True` 时，表示我们希望得到“verbose”输出：一份所有运行过的 test 的目录。

```python
>>> from doctest import run_docstring_examples
>>> run_docstring_examples(sum_naturals, globals(), True)
Finding tests in NoName
Trying:
    sum_naturals(10)
Expecting:
    55
ok
Trying:
    sum_naturals(100)
Expecting:
    5050
ok
```

当 function 的 return value 与预期结果不符时，`run_docstring_examples` function 会把这个问题作为一次 test 失败报告出来。

把 Python 写进文件时，只要用 doctest 命令行选项启动 Python，就可以运行文件中的所有 doctest：

```

python3 -m doctest <python_source_file>
```

有效测试的关键在于：实现新 function 之后立即编写（并运行）test。甚至在实现之前就先写一些 test 也是一种好做法，这样你心里就有了一些示例输入和输出。只对一个 function 进行测试的 test 称为 *unit test*。详尽的 unit testing 是良好程序设计的标志。

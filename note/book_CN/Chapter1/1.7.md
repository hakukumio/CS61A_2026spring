# 1.7 Recursive Functions

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=B2_8t2jyvX0)

如果某个 function 的 body 直接或间接地调用了该 function 自身，就称这个 function 是 *recursive* 的。也就是说，执行一个 recursive function 的 body 的过程，可能反过来又需要再次应用这个 function。Recursive function 在 Python 中并不使用任何特殊语法，但理解它们、写出它们确实需要下一些功夫。

我们先从一个示例问题开始：写一个 function，求一个自然数的各位数字之和。设计 recursive function 时，我们要寻找把一个问题拆解成更简单问题的途径。在这个例子中，可以用 operator `%` 和 `//` 把一个数拆成两部分：它的最后一位数字，以及去掉最后一位后剩下的部分。

```python
>>> 18117 % 10
7
>>> 18117 // 10
1811
```

18117 的各位数字之和是 `1+8+1+1+7 = 18`。正如我们可以拆分这个数，我们也可以把这个和拆成最后一位数字 7，以及去掉最后一位后其余数字之和 `1+8+1+1 = 11`。这种拆分方式给出了一个算法：要求数 `n` 的各位数字之和，就把它的最后一位数字 `n % 10` 加上 `n // 10` 的各位数字之和。有一个特殊情况：如果某个数只有一位，那么它的各位数字之和就是它本身。这个算法可以实现为一个 recursive function。

```python
>>> def sum_digits(n):
        """Return the sum of the digits of positive integer n."""
        if n < 10:
            return n
        else:
            all_but_last, last = n // 10, n % 10
            return sum_digits(all_but_last) + last
```

这个 `sum_digits` 的定义既完整又正确，尽管 `sum_digits` function 是在它自己的 body 内部被调用的。求一个数各位数字之和的问题被拆成了两步：先求去掉最后一位后其余数字之和，再加上最后一位。这两步都比原问题更简单。之所以说这个 function 是 recursive 的，是因为第一步与原问题属于同一类问题。也就是说，`sum_digits` 正是我们实现 `sum_digits` 所需要的那个 function。

```python
>>> sum_digits(9)
9
>>> sum_digits(18117)
18
>>> sum_digits(9437184)
36
>>> sum_digits(11408855402054064613470328848384)
126
```

借助我们的 environment 计算模型，我们可以精确地理解这个 recursive function 是如何成功应用的。不需要任何新规则。

```python

def sum_digits(n):
    if n < 10:
        return n
    else:
        all_but_last, last = n // 10, n % 10
        return sum_digits(all_but_last) + last

sum_digits(738)
```

当 `def` statement 执行时，名字 `sum_digits` 被绑定到一个新 function 上，但该 function 的 body 尚未执行。因此，`sum_digits` 的循环性质暂时还不成问题。接下来，用 738 调用 `sum_digits`：

1. 会为 `sum_digits` 创建一个 local frame，其中 `n` 绑定到 738，并在以该 frame 为起点的 environment 中执行 `sum_digits` 的 body。
2. 由于 738 不小于 10，第 4 行的 assignment statement 被执行，把 738 拆成 73 和 8。
3. 在接下来的 return statement 中，用 73 调用 `sum_digits`，73 就是当前 environment 中 `all_but_last` 的值。

3. 又为 `sum_digits` 创建了一个 local frame，这次 `n` 绑定到 73。`sum_digits` 的 body 再次在以该 frame 为起点的新 environment 中执行。
4. 由于 73 也不小于 10，73 被拆成 7 和 3，并用 7 调用 `sum_digits`，7 是在这个 frame 中 evaluate 得到的 `all_but_last` 的值。
5. 为 `sum_digits` 创建了第三个 local frame，`n` 绑定到 7。
6. 在以这个 frame 为起点的 environment 中，`n < 10` 成立，因此返回 7。
7. 在第二个 local frame 中，这个 return value 7 与 `last` 的值 3 相加，返回 10。
8. 在第一个 local frame 中，这个 return value 10 与 `last` 的值 8 相加，返回 18。

这个 recursive function 尽管具有循环性质，却能正确应用，因为它被应用了两次，而每次的 argument 都不同。此外，第二次应用是比第一次更简单的数位求和问题实例。为 `sum_digits(18117)` 这个 call 生成 environment diagram，你会看到对 `sum_digits` 的每一次相继调用所取的 argument 都比上一次更小，直到最终达到只有一位的输入。

这个例子还说明了，body 简单的 function 如何借助 recursion 演化出复杂的计算过程。

## 1.7.1 Recursive Functions 的剖析

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=8G7a8ANMwzQ)

在许多 recursive function 的 body 中都能发现一种常见的模式。body 以一个 *base case* 开头，即一条 conditional statement，它定义了该 function 在处理最简单的输入时的行为。对 `sum_digits` 而言，base case 就是任何一位数的 argument，我们直接返回这个 argument。有些 recursive function 会有多个 base case。

base case 之后跟着一个或多个 *recursive call*。Recursive call 总是具有某种特征：它们会把原问题简化。Recursive function 通过逐步简化问题来表达计算。例如，求 7 的各位数字之和比求 73 的各位数字之和更简单，而后者又比求 738 的各位数字之和更简单。每进行一次相继的调用，剩余待做的工作就更少。

Recursive function 解决问题的方式常常不同于我们此前用过的迭代式方法。考虑一个 function `fact` 用来计算 `n` 的阶乘，例如 `fact(4)` 计算 $4! = 4 \cdot
3 \cdot 2 \cdot 1 = 24$。

使用 `while` statement 的一种自然实现是，把直到 `n` 的每个正整数依次乘起来，累积出总数。

```python
>>> def fact_iter(n):
        total, k = 1, 1
        while k <= n:
            total, k = total * k, k + 1
        return total
```

```python
>>> fact_iter(4)
24
```

另一方面，阶乘的 recursive 实现可以把 `fact(n)` 表达为 `fact(n-1)`，也就是一个更简单的问题。Recursion 的 base case 是该问题最简单的形式：`fact(1)` 是 1。

```python

def fact(n):
    if n == 1:
        return 1
    else:
        return n * fact(n-1)

fact(4)
```

这两个阶乘 function 在概念上有所不同。迭代式的 function 从 base case 1 出发，通过把每一项逐次乘进来，构造出最终的总数。而 recursive 的 function 则直接从最后一项 `n` 和更简单问题的结果 `fact(n-1)` 构造出结果。

当 recursion 沿着 *fact* function 一次次作用于越来越简单的问题实例而层层“回溯”时，结果最终从 base case 开始被构造出来。Recursion 以把 argument 1 传给 `fact` 而结束；每一次调用的结果都依赖于下一次调用，直到抵达 base case 为止。

从阶乘这一数学 function 的标准定义出发，很容易验证这个 recursive function 的正确性：

\begin{align*}
(n-1)! &= (n-1) \cdot (n-2) \cdot \dots \cdot 1 \\
n! &= n \cdot (n-1) \cdot (n-2) \cdot \dots \cdot 1 \\
n! &= n \cdot (n-1)!
\end{align*}

虽然我们可以用计算模型来展开 recursion，但把 recursive call 看作 functional abstraction 往往更清晰。也就是说，我们不应该关心 `fact(n-1)` 在 `fact` 的 body 中是如何实现的；我们只需相信它会算出 `n-1` 的阶乘。把 recursive call 当作 functional abstraction 来对待，这种做法被称为 *recursive leap of faith*。我们用一个 function 自身来定义它，但在验证这个 function 的正确性时，只是相信那些更简单的情形会正确工作。在这个例子中，我们相信 `fact(n-1)` 会正确计算出 `(n-1)!`；我们只需检查在这个假设成立的前提下 `n!` 是否被正确计算。这样一来，验证 recursive function 的正确性就成了一种归纳证明。

Function *fact_iter* 与 *fact* 还有一个区别：前者必须引入两个额外的名字 `total` 和 `k`，而 recursive 实现并不需要它们。一般来说，迭代式的 function 必须维护一些在计算过程中不断变化的局部状态。在迭代的任意时刻，该状态都刻画了已完成工作所得到的结果以及剩余的工作量。例如，当 `k` 为 3、total 为 2 时，还剩两项 3 和 4 有待处理。而 *fact* 的特征则仅由它唯一的 argument `n` 决定。计算的状态完全蕴含在 environment 的结构之中：其中的 return value 承担了 `total` 的角色，并在不同的 frame 中把 `n` 绑定到不同的值，而不是显式地跟踪 `k`。

Recursive function 利用了 evaluate call expression 时把名字绑定到值的规则，从而常常免去了在迭代过程中正确地为局部名字赋值的麻烦。正因如此，recursive function 可能更容易被正确定义。不过，要学会识别 recursive function 所演化出的计算过程，肯定需要练习。

## 1.7.2 Mutual Recursion

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=IhY2cNaFktw)

当一个 recursive 过程被分配到两个互相调用的 function 中时，就称这些 function 是 *mutually recursive* 的。举个例子，考虑下面关于非负整数奇偶性的定义：

- 如果某个数比一个奇数大 1，那么它就是偶数
- 如果某个数比一个偶数大 1，那么它就是奇数
- 0 是偶数

利用这个定义，我们可以实现互为 recursive 的 function 来判断一个数是偶数还是奇数：

```python

def is_even(n):
    if n == 0:
        return True
    else:
        return is_odd(n-1)

def is_odd(n):
    if n == 0:
        return False
    else:
        return is_even(n-1)

result = is_even(4)
```

只要打破两个 function 之间的 abstraction boundary，mutually recursive 的 function 就能转变成单个 recursive function。在这个例子中，可以把 `is_odd` 的 body 合并进 `is_even` 的 body，同时确保在 `is_odd` 的 body 中把 `n` 换成 `n-1`，以反映传给它的 argument：

```python
>>> def is_even(n):
        if n == 0:
            return True
        else:
            if (n-1) == 0:
                return False
            else:
                return is_even((n-1)-1)
```

如此看来，mutual recursion 并不比简单的 recursion 更神秘或更强大，而且它提供了一种在复杂的 recursive 程序中维持 abstraction 的机制。

## 1.7.3 在 Recursive Functions 中打印

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=VYYkJ1OLXBw)

recursive function 所演化出的计算过程常常可以用调用 `print` 来可视化。作为例子，我们来实现一个 function `cascade`，它把一个数的所有前缀从最大到最小、再到最大依次打印出来。

```python
>>> def cascade(n):
        """Print a cascade of prefixes of n."""
        if n < 10:
            print(n)
        else:
            print(n)
            cascade(n//10)
            print(n)
```

```python
>>> cascade(2013)
2013
201
20
2
20
201
2013
```

在这个 recursive function 中，base case 是一位数，它会被打印出来。否则，一次 recursive call 会被放在两次 `print` 调用之间。

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=uK3KrG8qxPg)

base case 必须写在 recursive call 之前，这并非硬性要求。事实上，只要注意到 `print(n)` 在 conditional statement 的两个分支中都重复出现过，因此可以把它提前，这个 function 就能写得更紧凑。

```python
>>> def cascade(n):
        """Print a cascade of prefixes of n."""
        print(n)
        if n >= 10:
            cascade(n//10)
            print(n)
```

作为 mutual recursion 的另一个例子，考虑一个双人游戏：桌上最初有 `n` 颗石子。两个玩家轮流从桌上取走一颗或两颗石子，取走最后一颗石子的人获胜。假设 Alice 和 Bob 玩这个游戏，各自采用一个简单的策略：

- Alice 总是取走一颗石子
- 如果桌上的石子数是偶数，Bob 取走两颗，否则取走一颗

给定初始石子数 `n`，且由 Alice 先手，谁会获胜？

对这个问题的一种自然分解方式，是把每个策略封装在各自的 function 中。这样我们可以修改其中一个策略而不影响另一个，从而维持两者之间的 abstraction barrier。为了体现游戏逐轮进行的性质，这两个 function 在每一轮结束时互相调用。

```python
>>> def play_alice(n):
        if n == 0:
            print("Bob wins!")
        else:
            play_bob(n-1)
```

```python
>>> def play_bob(n):
        if n == 0:
            print("Alice wins!")
        elif is_even(n):
            play_alice(n-2)
        else:
            play_alice(n-1)
```

```python
>>> play_alice(20)
Bob wins!
```

在 `play_bob` 中我们看到，一个 function 的 body 里可能出现多次 recursive call。不过在这个例子中，每次调用 `play_bob` 都至多调用一次 `play_alice`。在下一节里，我们考虑单次 function 调用就引发多次直接 recursive call 时会发生什么。

## 1.7.4 Tree Recursion

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=ls0GsJyLVLw)

另一种常见的计算模式称为 tree recursion，即一个 function 多次调用自身。举个例子，考虑计算 Fibonacci 数列：其中每个数都是前两个数之和。

```python

def fib(n):
    if n == 1:
        return 0
    if n == 2:
        return 1
    else:
        return fib(n-2) + fib(n-1)

result = fib(6)
```

与我们此前的几种尝试相比，这个 recursive 定义极具吸引力：它精确地对应了人们熟悉的 Fibonacci 数的定义。一个包含多次 recursive call 的 function 被称为 *tree recursive*，因为每次调用都会分支成多个更小的调用，而每个更小的调用又分支成更小的调用，就像一棵树从树干向外伸展时，枝条越来越短却越来越多。

我们此前已经能够不用 tree recursion 来定义计算 Fibonacci 数的 function。事实上，我们之前的几种尝试效率更高，这个话题会在本书后面讨论。接下来，我们考虑一个问题，它的 tree recursive 解法比其他任何迭代式解法都简单得多。

## 1.7.5 示例：分拆

> **Video:** [Watch on YouTube](https://www.youtube.com/watch?v=DvgT4dnSMVM)

正整数 `n` 使用最大不超过 `m` 的部分的分拆数，是指把 `n` 表示成若干个按递增顺序排列、且每个都不超过 `m` 的正整数之和的方法数。例如，6 使用不超过 4 的部分的分拆数是 9。

1. `6 = 2 + 4`
2. `6 = 1 + 1 + 4`
3. `6 = 3 + 3`
4. `6 = 1 + 2 + 3`
5. `6 = 1 + 1 + 1 + 3`
6. `6 = 2 + 2 + 2`
7. `6 = 1 + 1 + 2 + 2`
8. `6 = 1 + 1 + 1 + 1 + 2`
9. `6 = 1 + 1 + 1 + 1 + 1 + 1`

我们将定义一个 function `count_partitions(n, m)`，它返回用不超过 `m` 的部分分拆 `n` 的不同方法的数目。基于下面这个观察，这个 function 有一个作为 tree-recursive function 的简单解法：

用不超过 `m` 的整数分拆 `n` 的方法数，等于

1. 用不超过 `m` 的整数分拆 `n-m` 的方法数，加上
2. 用不超过 `m-1` 的整数分拆 `n` 的方法数。

要明白为什么这一点成立，请注意：分拆 `n` 的所有方法可以分成两组——至少包含一个 `m` 的那些，以及不包含的那些。此外，第一组中的每个分拆都是把 `n-m` 的一个分拆后面再补上一个 `m`。在上面的例子中，前两个分拆含有 4，其余的则不含。

因此，我们可以 recursive 地把用不超过 `m` 的整数分拆 `n` 的问题约化为两个更简单的问题：(1) 分拆一个更小的数 `n-m`；(2) 用不超过 `m-1` 的更小部分来分拆。

为了完成这个实现，我们需要指明下面这些 base case：

1. 分拆 0 有一种方法：不包含任何部分。
2. 分拆一个负数 `n` 有 0 种方法。
3. 用大小为 0 或更小的部分分拆任何大于 0 的 `n` 都有 0 种方法。

```python
>>> def count_partitions(n, m):
        """Count the ways to partition n using parts up to m."""
        if n == 0:
            return 1
        elif n < 0:
            return 0
        elif m == 0:
            return 0
        else:
            return count_partitions(n-m, m) + count_partitions(n, m-1)
```

```python
>>> count_partitions(6, 4)
9
>>> count_partitions(5, 5)
7
>>> count_partitions(10, 10)
42
>>> count_partitions(15, 15)
176
>>> count_partitions(20, 20)
627
```

我们可以把一个 tree-recursive function 看作在探索各种不同的可能性。在这个例子中，我们探索了使用一个大小为 `m` 的部分的可能性，以及不使用它的可能性。第一次和第二次 recursive call 就分别对应这两种可能性。

不用 recursion 来实现这个 function 会复杂得多。有兴趣的读者不妨一试。

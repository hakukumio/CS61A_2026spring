# 4.4 Logic Programming

本节介绍一门为本教材专门设计的 declarative query language，名为 `logic`。它基于 [Prolog](http://en.wikipedia.org/wiki/Prolog) 以及[《计算机程序的构造和解释》](http://mitpress.mit.edu/sicp/full-text/book/book-Z-H-29.html#%_sec_4.4.1)中的 declarative language。数据记录表示为 Scheme list，query 表示为 Scheme 值。[logic](http://composingprograms.com/examples/logic/logic.py.html) interpreter 是一个完整的实现，它依赖于上一章的 Scheme 项目。

## 4.4.1 fact 与 query

数据库存储的记录表示系统中的 fact。query interpreter 的用途是取回直接从数据库记录中得到的 fact 集合，以及使用逻辑推理从数据库中推导出新的 fact。`logic` 语言中的 `fact` statement 由关键字 `fact` 之后的一个或多个 list 组成。简单的 fact 就是一个单独的 list。一位对美国历任总统感兴趣的养狗人，可能会用 `logic` 语言这样记录她所养的狗的血统：

```

(fact (parent abraham barack))
(fact (parent abraham clinton))
(fact (parent delano herbert))
(fact (parent fillmore abraham))
(fact (parent fillmore delano))
(fact (parent fillmore grover))
(fact (parent eisenhower fillmore))
```

每条 fact 都不像 Scheme expression 那样是 procedure 应用，而是一条被声明的 *relation*。“狗 Abraham 是 Barack 的父辈，”第一条 fact 这样声明。relation 的类型无需预先定义。relation 不是被应用的，而是与 query 相匹配。

query 也由一个或多个 list 组成，但以关键字 `query` 开头。query 可以包含变量，也就是以问号开头的符号。query interpreter 会把变量与 fact 相匹配：

```

(query (parent abraham ?child))
```

query interpreter 会以 `Success!` 作为回应，表示该 query 与某条 fact 相匹配。下面几行显示了使该 query 与数据库中的 fact 相匹配的变量 `?child` 的替换值。

**复合 fact。**fact 也可以包含变量以及多个 sub-expression。含多个 expression 的 fact 以结论开头，后面跟着若干假设。要使结论为真，所有假设都必须得到满足：

```

(fact <conclusion> <hypothesis0> <hypothesis1> ... <hypothesisN>)
```

例如，可以基于数据库中已有的关于父母的 fact 来声明关于子女的 fact：

```

(fact (child ?c ?p) (parent ?p ?c))
```

上面这条 fact 可以读作：“`?c` 是 `?p` 的孩子，只要 `?p` 是 `?c` 的父母。”现在 query 就可以引用这条 fact：

```

(query (child ?child fillmore))
```

上面的 query 要求 query interpreter 把定义 `child` 的那条 fact 与关于 `fillmore` 的若干 parent fact 结合起来。语言的用户不需要知道这些信息是如何结合的，只需要知道结果具有某种特定的形式。在已有 fact 给定的情况下，证明 `(child abraham fillmore)` 为真，是 query interpreter 的任务。

query 不一定要包含变量；它也可以只是验证一条 fact：

```

(query (child herbert delano))
```

如果 query 没有匹配到任何 fact，就会返回失败：

```

(query (child eisenhower ?parent))
```

**否定。**我们可以使用特殊关键字 `not` 来检查某个 query 是否不匹配任何 fact：

```

(query (not <relation>))
```

如果 `<relation>` 失败，该 query 就成功；如果 `<relation>` 成功，该 query 就失败。这一思想称为*否定即失败*。

```

(query (not (parent abraham clinton)))
```

```

(query (not (parent abraham barack)))
```

有时，否定即失败可能与人们预期的否定工作方式相悖。想一想下面这个 query 的结果：

```

(query (not (parent abraham ?who)))
```

这个 query 为什么会失败？当然，有很多符号可以绑定到 `?who`，使该条件成立。然而，否定的步骤要求我们首先检查 relation `(parent abraham ?who)`。这个 relation 会成功，因为 `?who` 可以绑定到 `barack` 或 `clinton`。既然该 relation 成功，它的否定就必然失败。

## 4.4.2 recursive fact

`logic` 语言也允许 recursive fact。也就是说，一条 fact 的结论可以依赖于包含相同符号的假设。例如，ancestor relation 用两条 fact 定义。如果 `?a` 是 `?y` 的父母，或者 `?a` 是 `?y` 某个祖先的父母，那么 `?a` 就是 `?y` 的祖先：

```

(fact (ancestor ?a ?y) (parent ?a ?y))
(fact (ancestor ?a ?y) (parent ?a ?z) (ancestor ?z ?y))
```

于是，单个 query 就能列出 `herbert` 的所有祖先：

```

(query (ancestor ?a herbert))
```

**复合 query。**一个 query 可以有多个 subexpression，此时必须有一组符号到变量的赋值同时满足它们全部。如果一个变量在 query 中出现多次，那么它在每个上下文中都必须取相同的值。下面的 query 查找 `herbert` 和 `barack` 共同的祖先：

```

(query (ancestor ?a barack) (ancestor ?a herbert))
```

recursive fact 可能需要很长的推理链，才能把 query 与数据库中已有的 fact 匹配起来。例如，要证明 fact `(ancestor fillmore herbert)`，我们必须依次证明下列每一条 fact：

```

(parent delano herbert)       ; (1), a simple fact
(ancestor delano herbert)     ; (2), from (1) and the 1st ancestor fact
(parent fillmore delano)      ; (3), a simple fact
(ancestor fillmore herbert)   ; (4), from (2), (3), & the 2nd ancestor fact
```

这样一来，只要 query interpreter 能够发现，单条 fact 就可以蕴含大量额外的 fact，甚至无穷多条。

**层次化 fact。**到目前为止，每个 fact 和 query expression 都只是符号的 list。此外，fact 和 query 的 list 还可以包含 list，从而提供了一种表示层次化数据的方式。每只狗的颜色可以与名字一起存放在一条额外的记录中：

```

(fact (dog (name abraham) (color white)))
(fact (dog (name barack) (color tan)))
(fact (dog (name clinton) (color white)))
(fact (dog (name delano) (color white)))
(fact (dog (name eisenhower) (color tan)))
(fact (dog (name fillmore) (color brown)))
(fact (dog (name grover) (color tan)))
(fact (dog (name herbert) (color brown)))
```

query 既可以把层次化 fact 的完整结构写出来，也可以把变量与整个 list 相匹配：

```

(query (dog (name clinton) (color ?color)))
```

```

(query (dog (name clinton) ?info))
```

数据库的强大之处很大程度上在于，query interpreter 能够在单个 query 中把多种 fact 连接起来。下面的 query 找出所有这样的狗对：其中一只是另一只的祖先，并且它们颜色相同：

```

(query (dog (name ?name) (color ?color))
       (ancestor ?ancestor ?name)
       (dog (name ?ancestor) (color ?color)))
```

变量不仅可以引用层次化记录中的 list，还可以使用 dot notation。跟在点号之后的变量会匹配一条 fact 中剩余的 list。dotted list 既可能出现在 fact 中，也可能出现在 query 中。下面的例子通过列出历代祖先来构造狗的血统谱系。年轻的 `barack` 出身于一条令人尊敬的总统小狗血脉：

```

(fact (pedigree ?name) (dog (name ?name) . ?details))
(fact (pedigree ?child ?parent . ?rest)
      (parent ?parent ?child)
      (pedigree ?parent . ?rest))
```

```

(query (pedigree barack . ?lineage))
```

declarative programming 或 logic programming 能够以惊人的效率表达 fact 之间的关系。例如，如果我们想表达：两个 list 可以拼接成一个更长的 list，其中先是一个 list 的 element，接着是第二个 list 的 element，那么我们陈述两条规则。首先，一条 base case 声明：把空 list 拼接到任何 list 上，得到的都是那个 list：

```

(fact (append-to-form () ?x ?x))
```

其次，一条 recursive fact 声明：以 `?a` 为第一个 element、`?r` 为其余部分的 list，与 list `?y` 拼接后，形成以 `?a` 为第一个 element、以某个拼接得到的 `?z` 为其余部分的 list。要使这一 relation 成立，必须满足 `?r` 与 `?y` 拼接后得到 `?z`：

```

(fact (append-to-form (?a . ?r) ?y (?a . ?z)) (append-to-form ?r ?y ?z))
```

有了这两条 fact，query interpreter 就能计算任意两个 list 拼接的结果：

```

(query (append-to-form (a b c) (d e) ?result))
```

此外，它还能计算出所有可能的 list 对 `?left` 和 `?right`，它们拼接后可以得到 list `(a b c d e)`：

```

(query (append-to-form ?left ?right (a b c d e)))
```

尽管我们的 query interpreter 看起来相当智能，但我们会看到，它只是通过一个简单操作反复执行多次来找出这些组合：在 environment 中匹配两个含有变量的 list。

# 4.5 Unification

本节介绍在 `logic` 语言中执行推理的 query interpreter 的一种实现。这个 interpreter 是一个通用的问题求解器，但在它能解决的问题规模和类型上有很大的局限。更复杂的逻辑编程语言确实存在，但构造高效的推理过程至今仍是计算机科学中一个活跃的研究课题。

query interpreter 执行的基本操作称为 *unification*。Unification 是一种把 query 与 fact 相匹配的通用方法，二者都可能包含变量。query interpreter 反复应用这一操作：先把原始 query 与各条 fact 的结论相匹配，再把 fact 的假设与数据库中的其他结论相匹配。在此过程中，query interpreter 会在与某个 query 相关的所有 fact 构成的空间中进行搜索。如果它找到一种给变量赋值从而支持该 query 的方式，就把这组赋值作为成功的结果返回。

## 4.5.1 pattern matching

为了返回与某个 query 相匹配的简单 fact，interpreter 必须把含有变量的 query 与不含变量的 fact 相匹配。例如，如果变量 `?child` 取值 `barack`，那么 query `(query (parent abraham ?child))` 与 fact `(fact (parent abraham barack))` 就相匹配。

一般来说，如果存在一组变量名到值的 binding，使得把这些值代入 pattern 后能得到某个 expression（可能是一个嵌套的 Scheme list），那么就称该 pattern 与这个 expression 相匹配。

例如，expression `((a b) c (a b))` 与 pattern `(?x c ?x)` 相匹配，其中变量 `?x` 绑定到值 `(a b)`。同一个 expression 也与 pattern `((a ?y) ?z (a b))` 相匹配，其中变量 `?y` 绑定到 `b`，`?z` 绑定到 `c`。

## 4.5.2 表示 fact 与 query

导入所提供的 [logic](http://composingprograms.com/examples/logic/logic.py.html) 示例程序，就可以复现下面的例子。

```python
>>> from logic import *
```

在 logic 语言中，query 和 fact 都表示为 Scheme list，使用与上一章相同的 `Pair` class 和 `nil` object。例如，query expression `(?x c ?x)` 表示为嵌套的 `Pair` instance。

```python
>>> read_line("(?x c ?x)")
Pair('?x', Pair('c', Pair('?x', nil)))
```

与 Scheme 项目一样，把符号绑定到值的 environment 用 `Frame` class 的 instance 表示，它有一个名为 `bindings` 的 attribute。

`logic` 语言中执行 pattern matching 的 function 叫做 `unify`。它接受两个输入 `e` 和 `f`，以及一个记录变量到值 binding 的 environment `env`。

```python
>>> e = read_line("((a b) c (a b))")
>>> f = read_line("(?x c ?x)")
>>> env = Frame(None)
>>> unify(e, f, env)
True
>>> env.bindings
{'?x': Pair('a', Pair('b', nil))}
>>> print(env.lookup('?x'))
(a b)
```

在上面，`unify` 返回 `True` 这一 return value 表明 pattern `f` 能够匹配 expression `e`。unification 的结果记录在 `env` 中的 binding 里，即把 `?x` 绑定到 `(a b)`。

## 4.5.3 unification 算法

Unification 是 pattern matching 的推广，它试图在两个可能都含有变量的 expression 之间找到一种映射。`unify` function 通过一个 recursive 过程实现 unification，它对两个 expression 的对应部分执行 unification，直到遇到矛盾，或者能够建立起对所有变量都可行的 binding 为止。

让我们从一个例子开始。pattern `(?x ?x)` 能够匹配 pattern `((a ?y c) (a b ?z))`，因为存在一个不含变量的 expression 能同时匹配二者：`((a b c) (a b c))`。Unification 通过下列步骤找出这个解：

1. 为了匹配两个 pattern 的第一个 element，变量 `?x` 被绑定到 expression `(a ?y c)`。
2. 为了匹配两个 pattern 的第二个 element，首先把变量 `?x` 替换为它的值。然后，通过把 `?y` 绑定到 `b`、把 `?z` 绑定到 `c`，使 `(a ?y c)` 与 `(a b ?z)` 相匹配。

结果，放入传给 `unify` 的 environment 中的 binding 含有 `?x`、`?y` 和 `?z` 的条目：

```python
>>> e = read_line("(?x ?x)")
>>> f = read_line(" ((a ?y c) (a b ?z))")
>>> env = Frame(None)
>>> unify(e, f, env)
True
>>> env.bindings
{'?z': 'c', '?y': 'b', '?x': Pair('a', Pair('?y', Pair('c', nil)))}
```

unification 的结果可能把变量绑定到一个同样含有变量的 expression 上，就像上面看到的 `?x` 绑定到 `(a ?y c)`。`bind` function 会 recursive 地反复把 expression 中的所有变量绑定到它们的值，直到其中不再有未绑定的变量为止。

```python
>>> print(bind(e, env))
((a b c) (a b c))
```

一般来说，unification 通过检查若干条件来进行。`unify` 的实现直接对应下面的描述。

1. 如果两个输入 `e` 和 `f` 是变量，就把它们替换为各自的值。
2. 如果 `e` 和 `f` 相等，unification 成功。
3. 如果 `e` 是变量，unification 成功，并把 `e` 绑定到 `f`。
4. 如果 `f` 是变量，unification 成功，并把 `f` 绑定到 `e`。
5. 如果二者都不是变量、都不是 list，且彼此不相等，那么 `e` 和 `f` 无法被 unify，因此 unification 失败。
6. 如果以上情况都不成立，那么 `e` 和 `f` 都是 pair，于是对它们对应的第一个和第二个 element 分别执行 unification。

```python
>>> def unify(e, f, env):
        """Destructively extend ENV so as to unify (make equal) e and f, returning
        True if this succeeds and False otherwise.  ENV may be modified in either
        case (its existing bindings are never changed)."""
        e = lookup(e, env)
        f = lookup(f, env)
        if e == f:
            return True
        elif isvar(e):
            env.define(e, f)
            return True
        elif isvar(f):
            env.define(f, e)
            return True
        elif scheme_atomp(e) or scheme_atomp(f):
            return False
        else:
            return unify(e.first, f.first, env) and unify(e.second, f.second, env)
```

## 4.5.4 证明

理解 `logic` 语言的一种方式是把它看作形式系统中断言的证明器。每条声明的 fact 都在形式系统中建立一条公理，而每个 query 都必须由 query interpreter 从这些公理出发来建立。也就是说，每个 query 都断言：存在对其变量的一组赋值，使得它的所有 sub-expression 同时由系统中的 fact 推出。query interpreter 的作用就是验证这一点是否成立。

例如，给定关于狗的 fact 集合，我们可以断言 Clinton 和某只棕褐色狗有某个共同的祖先。只有当 query interpreter 能够建立该断言为真时，它才输出 `Success!`。作为副产品，它会告诉我们那个共同祖先以及那只棕褐色狗的名字：

```

(fact (parent abraham barack))
(fact (parent abraham clinton))
(fact (parent delano herbert))
(fact (parent fillmore abraham))
(fact (parent fillmore delano))
(fact (parent fillmore grover))
(fact (parent eisenhower fillmore))

(fact (ancestor ?a ?y) (parent ?a ?y))
(fact (ancestor ?a ?y) (parent ?a ?z) (ancestor ?z ?y))

(fact (dog (name abraham) (color white)))
(fact (dog (name barack) (color tan)))
(fact (dog (name clinton) (color white)))
(fact (dog (name delano) (color white)))
(fact (dog (name eisenhower) (color tan)))
(fact (dog (name fillmore) (color brown)))
(fact (dog (name grover) (color tan)))
(fact (dog (name herbert) (color brown)))
```

```

(query (ancestor ?a clinton)
       (ancestor ?a ?brown-dog)
       (dog (name ?brown-dog) (color brown)))
```

结果中显示的这三组赋值，都是“在给定 fact 的情况下该 query 为真”这一更大证明的踪迹。完整的证明会包含所用到的全部 fact，例如包括 `(parent abraham clinton)` 和 `(parent fillmore abraham)`。

## 4.5.5 搜索

为了从系统中已经建立的 fact 出发建立某个 query，query interpreter 会在所有可能的 fact 构成的空间中进行搜索。Unification 是对两个 expression 进行 pattern matching 的 primitive 操作。query interpreter 中的*搜索过程*决定要对哪些 expression 执行 unification，以找到一组串联起来能够建立该 query 的 fact。

recursive 的 `search` function 实现了 `logic` 语言的搜索过程。它的输入包括：query 中 `clauses` 的 Scheme list、一个包含符号到值当前 binding 的 environment `env`（初始为空），以及已经串联起来的规则链的 `depth`。

```python
>>> def search(clauses, env, depth):
        """Search for an application of rules to establish all the CLAUSES,
        non-destructively extending the unifier ENV.  Limit the search to
        the nested application of DEPTH rules."""
        if clauses is nil:
            yield env
        elif DEPTH_LIMIT is None or depth <= DEPTH_LIMIT:
            if clauses.first.first in ('not', '~'):
                clause = ground(clauses.first.second, env)
                try:
                    next(search(clause, glob, 0))
                except StopIteration:
                    env_head = Frame(env)
                    for result in search(clauses.second, env_head, depth+1):
                        yield result
            else:
                for fact in facts:
                    fact = rename_variables(fact, get_unique_id())
                    env_head = Frame(env)
                    if unify(fact.first, clauses.first, env_head):
                        for env_rule in search(fact.second, env_head, depth+1):
                            for result in search(clauses.second, env_rule, depth+1):
                                yield result
```

为了同时满足所有 clause 的搜索从第一个 clause 开始。在第一个 clause 被否定的特殊情况下，我们不是尝试把 query 的第一个 clause 与某条 fact 相 unify，而是通过一次对 `search` 的 recursive 调用，检查不存在这样的 unification 可能。如果这次 recursive 调用没有产生任何结果，我们就用其余的 clause 继续搜索过程。如果 unification 是可能的，我们立刻失败。

如果第一个 clause 没有被否定，那么对于数据库中的每条 fact，`search` 都尝试把该 fact 的第一个 clause 与 query 的第一个 clause 相 unify。Unification 在一个新的 environment `env_head` 中执行。作为 unification 的 side effect，变量在 `env_head` 中被绑定到相应的值。

如果 unification 成功，那么这个 clause 就与该规则的结论相匹配。接下来的 `for` statement 尝试建立该规则的假设，从而确立结论。正是在这里，recursive 规则的假设会被 recursive 地传给 `search`，以便得到建立。

最后，对于 `fact.second` 的每一次成功搜索，得到的结果 environment 都会绑定到 `env_rule`。有了这些值到变量的 binding，最后的 `for` statement 就会搜索并建立初始 query 中其余的 clause。任何成功的结果都通过内层的 `yield` statement 返回。

**Unique names.** Unification 假定 `e` 和 `f` 之间没有共享的变量。然而，在 `logic` 语言的 fact 和 query 中，我们常常重复使用变量名。我们不希望把一条 fact 中的 `?x` 与另一条 fact 中的 `?x` 混为一谈；这些变量彼此无关。为了确保名字不会被混淆，在把一条 fact 传入 unify 之前，会用 `rename_variables` 为它附加一个唯一的整数，从而把其中的变量名替换为唯一的名字。

```python
>>> def rename_variables(expr, n):
        """Rename all variables in EXPR with an identifier N."""
        if isvar(expr):
            return expr + '_' + str(n)
        elif scheme_pairp(expr):
            return Pair(rename_variables(expr.first, n),
                        rename_variables(expr.second, n))
        else:
            return expr
```

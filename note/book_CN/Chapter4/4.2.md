# 4.2 隐式 sequence

一个 sequence 可以被表示出来，而不必将每个 element 都显式地存储在计算机的内存中。也就是说，我们可以构造一个 object，它提供对某个顺序数据集中所有 element 的访问，而不必提前计算每个 element 的值。相反，我们按需计算 element。

这个想法的一个例子出现在第 2 章介绍的 `range` 容器类型中。一个 `range` 表示一段连续的、有界的整数 sequence。然而，该 sequence 的每个 element 并非都显式地表示在内存中。相反，当从 `range` 中请求一个 element 时，它才被计算出来。因此，我们可以表示非常大的整数 range，而不必使用大块内存。只有 range 的两个端点作为 `range` object 的一部分被存储起来。

```python
>>> r = range(10000, 1000000000)
>>> r[45006230]
45016230
```

在这个例子中，当这个 range instance 被构造时，range 中全部的 999,990,000 个整数并不会都被存储起来。相反，range object 把第一个 element 10,000 加到 index 45,006,230 上，从而产生 element 45,016,230。按需计算值，而不是从已有的表示中取回它们，是 *lazy* computation 的一个例子。在计算机科学中，*lazy computation* 描述任何把值的计算推迟到该值被需要时才进行的程序。

## 4.2.1 Iterator

Python 和许多其他编程语言提供了一种统一的方式来顺序处理容器值中的 element，称为 iterator。*iterator* 是一个 object，它逐个提供对值的顺序访问。

iterator abstraction 有两个组成部分：一种获取正在被处理的 sequence 中下一个 element 的机制，以及一种表示该 sequence 已经到达末尾、不再有剩余 element 的机制。对于任何容器，例如 list 或 range，都可以通过调用内置的 `iter` function 来获得一个 iterator。调用内置的 `next` function 可以访问 iterator 的内容。

```python
>>> primes = [2, 3, 5, 7]
>>> type(primes)
>>> iterator = iter(primes)
>>> type(iterator)
>>> next(iterator)
2
>>> next(iterator)
3
>>> next(iterator)
5
```

Python 表示不再有可用值的方式是：在调用 `next` 时抛出 `StopIteration` exception。这个 exception 可以用 `try` statement 来处理。

```python
>>> next(iterator)
7
>>> next(iterator)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
>>> try:
        next(iterator)
    except StopIteration:
        print('No more values')
No more values
```

一个 iterator 维护局部状态来表示它在某个 sequence 中的位置。每次调用 `next`，该位置就向前推进。两个不同的 iterator 可以追踪同一个 sequence 中的两个不同位置。然而，同一个 iterator 的两个名字会共享同一个位置，因为它们共享同一个值。

```python
>>> r = range(3, 13)
>>> s = iter(r)  # 1st iterator over r
>>> next(s)
3
>>> next(s)
4
>>> t = iter(r)  # 2nd iterator over r
>>> next(t)
3
>>> next(t)
4
>>> u = t        # Alternate name for the 2nd iterator
>>> next(u)
5
>>> next(u)
6
```

推进第二个 iterator 不会影响第一个。由于第一个 iterator 最后返回的值是 4，所以它的位置决定它接下来返回 5。另一方面，第二个 iterator 的位置决定它接下来返回 7。

```python
>>> next(s)
5
>>> next(t)
7
```

对一个 iterator 调用 `iter` 会返回那个 iterator 本身，而不是一个副本。Python 之所以包含这一行为，是为了让程序员可以对一个值调用 `iter` 来获得 iterator，而不必担心它究竟是一个 iterator 还是一个容器。

```python
>>> v = iter(t)  # Another alterante name for the 2nd iterator
>>> next(v)
8
>>> next(u)
9
>>> next(t)
10
```

iterator 的用处来源于这样一个事实：iterator 底层的系列数据可能并未显式地表示在内存中。iterator 提供了一种机制，用来依次考虑一系列值中的每一个，但这些 element 并不需要同时被存储。相反，当从 iterator 中请求下一个 element 时，该 element 可以按需计算，而不是从已有的内存来源中取回。

range 能够惰性地计算 sequence 的 element，是因为它所表示的 sequence 是均匀的，任何 element 都很容易从 range 的起始和结束边界计算出来。iterator 允许对更广泛的一类底层顺序数据集进行惰性生成，因为它们不需要提供对底层系列中任意 element 的访问。相反，iterator 只需要在每次请求另一个 element 时，按顺序计算系列中的下一个 element。虽然不如访问 sequence 的任意 element（称为 *random access*）那样灵活，但对顺序数据的 *sequential access* 通常足以满足数据处理应用的需要。

## 4.2.2 Iterable

任何能够产生 iterator 的值都称为 *iterable* 值。在 Python 中，iterable 值就是任何可以传给内置 `iter` function 的东西。iterable 包括 string 和 tuple 这样的 sequence 值，也包括 set 和 dict 这样的其他容器。iterator 本身也是 iterable，因为它们可以传给 `iter` function。

## 4.2.3 内置 iterator

有几个内置的 function 接受 iterable 值作为 argument 并返回 iterator。这些 function 被广泛用于惰性的 sequence 处理。

`map` function 是惰性的：调用它并不会执行计算其结果 element 所需的运算。相反，它创建了一个 iterator object，如果使用 `next` 查询，它就能返回结果。我们可以在下面的例子中观察到这一事实：其中对 `print` 的调用被推迟，直到从 `doubled` iterator 请求相应的 element 时才执行。

```python
>>> def double_and_print(x):
        print('***', x, '=>', 2*x, '***')
        return 2*x
>>> s = range(3, 7)
>>> doubled = map(double_and_print, s)  # double_and_print not yet called
>>> next(doubled)                       # double_and_print called once
*** 3 => 6 ***
6
>>> next(doubled)                       # double_and_print called again
*** 4 => 8 ***
8
>>> list(doubled)                       # double_and_print called twice more
*** 5 => 10 ***
*** 6 => 12 ***
[10, 12]
```

## 4.2.4 for statement

Python 中的 `for` statement 作用于 iterator。如果 object 具有一个返回 *iterator* 的 `__iter__` method，那么它就是 *iterable* 的（这是一种 interface）。Iterable object 可以作为 `for` statement 头部中 `<expression>` 的值：

```

for <name> in <expression>:
    <suite>
```

为了执行一个 `for` statement，Python 会 evaluate 头部的 `<expression>`，它必须产生一个 iterable 值。然后，在该值上调用 `__iter__` method。在抛出 `StopIteration` exception 之前，Python 会反复在该 iterator 上调用 `__next__` method，并把结果绑定到 `for` statement 中的 `<name>` 上。接着，它执行 `<suite>`。

```python
>>> counts = [1, 2, 3]
>>> for item in counts:
        print(item)
1
2
3
```

在上面的例子中，`counts` list 从它的 `__iter__()` method 返回一个 iterator。然后 `for` statement 反复调用该 iterator 的 `__next__()` method，并每次都把返回的值赋给 `item`。这个过程一直持续到该 iterator 抛出 `StopIteration` exception，此时 `for` statement 的执行便结束了。

借助我们对 iterator 的了解，我们可以用 `while`、赋值和 `try` statement 来实现 `for` statement 的执行规则。

```python
>>> items = counts.__iter__()
>>> try:
        while True:
            item = items.__next__()
            print(item)
    except StopIteration:
        pass
1
2
3
```

在上面的代码中，通过调用 `counts` 的 `__iter__` method 返回的 iterator 被绑定到名字 `items` 上，以便可以依次查询每一个 element。`StopIteration` exception 的处理子句什么也不做，但处理这个 exception 提供了一种退出 `while` loop 的控制机制。

要在 for 循环中使用 iterator，该 iterator 也必须有一个 `__iter__` method。Python 文档中的 Iterator 类型 <http://docs.python.org/3/library/stdtypes.html#iterator-types> 小节建议，iterator 应当有一个返回该 iterator 本身的 `__iter__` method，这样所有 iterator 就都是 iterable 的。

## 4.2.5 Generator 与 yield statement

上面出现的 `Letters` 和 `Positives` object 要求我们在 object 中引入一个新的字段 `self.current`，以追踪在 sequence 中的进度。对于上面展示的那种简单 sequence，这很容易做到。然而，对于复杂的 sequence，`__next__` method 可能很难在计算中保存自己的位置。Generator 让我们能够借助 Python interpreter 的特性来定义更复杂的迭代。

*generator* 是由一类特殊的 function 返回的 iterator，这类 function 称为 *generator function*。Generator function 与普通 function 的区别在于：它们的主体中不含 `return` statement，而是使用 `yield` statement 来返回系列中的 element。

Generator 不使用 object 的 attribute 来追踪它在系列中的进度。相反，它们控制 generator function 的执行：每当 generator 的 `__next__` method 被调用时，generator function 就会一直运行，直到下一个 `yield` statement 被执行。用 generator function 实现 `Letters` iterator 可以紧凑得多。

```python
>>> def letters_generator():
        current = 'a'
        while current <= 'd':
            yield current
            current = chr(ord(current)+1)
```

```python
>>> for letter in letters_generator():
        print(letter)
a
b
c
d
```

即使我们从未显式地定义 `__iter__` 或 `__next__` method，`yield` statement 也表明我们正在定义一个 generator function。被调用时，generator function 不会返回某个特定的被 yield 的值，而是返回一个 `generator`（它是一种 iterator），它本身可以返回被 yield 的值。generator object 具有 `__iter__` 和 `__next__` method，每次调用 `__next__` 都会让 generator function 从上次离开的地方继续执行，直到另一个 `yield` statement 被执行。

第一次调用 `__next__` 时，程序会执行 `letters_generator` function 主体中的 statement，直到遇到 `yield` statement。然后，它暂停并返回 `current` 的值。`yield` statement 不会销毁新创建的 environment，而是把它保留下来供以后使用。当再次调用 `__next__` 时，执行会从上次离开的地方继续。`current` 的值以及 `letters_generator` 的 scope 中任何其他被绑定的名字的值，都会在后续对 `__next__` 的调用之间保持不变。

我们可以通过手动调用 `____next__()` 来逐步走查这个 generator：

```python
>>> letters = letters_generator()
>>> type(letters)
<class 'generator'>
>>> letters.__next__()
'a'
>>> letters.__next__()
'b'
>>> letters.__next__()
'c'
>>> letters.__next__()
'd'
>>> letters.__next__()
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
StopIteration
```

generator 在第一次调用 `__next__` 之前，不会开始执行其 generator function 主体中的任何 statement。每当它的 generator function 返回时，generator 就会抛出 `StopIteration` exception。

## 4.2.6 Iterable interface

如果一个 object 在它的 `__iter__` method 被调用时返回一个 iterator，那么它就是 iterable 的。Iterable 值表示数据集合，它们提供一种固定的表示，可以产生不止一个 iterator。

例如，下面 `Letters` class 的一个 instance 表示一段连续的字母 sequence。每次它的 `__iter__` method 被调用时，都会构造一个新的 `LetterIter` instance，从而可以顺序访问该 sequence 的内容。

```python
>>> class Letters:
        def __init__(self, start='a', end='e'):
            self.start = start
            self.end = end
        def __iter__(self):
            return LetterIter(self.start, self.end)
```

内置的 `iter` function 会在它的 argument 上调用 `__iter__` method。在下面的一系列 expression 中，两个从同一个 iterable sequence 派生出来的 iterator 各自独立地按顺序 yield 字母。

```python
>>> b_to_k = Letters('b', 'k')
>>> first_iterator = b_to_k.__iter__()
>>> next(first_iterator)
'b'
>>> next(first_iterator)
'c'
>>> second_iterator = iter(b_to_k)
>>> second_iterator.__next__()
'b'
>>> first_iterator.__next__()
'd'
>>> first_iterator.__next__()
'e'
>>> second_iterator.__next__()
'c'
>>> second_iterator.__next__()
'd'
```

iterable 的 `Letters` instance `b_to_k` 与 `LetterIter` iterator instance `first_iterator` 和 `second_iterator` 的不同之处在于：`Letters` instance 不会改变，而 iterator instance 会随每次对 `next` 的调用（等价地说，每次对 `__next__` 的调用）而改变。iterator 追踪在顺序数据中的进度，而 iterable 表示数据本身。

Python 中许多内置的 function 接受 iterable argument 并返回 iterator。例如，`map` function 接受一个 function 和一个 iterable。它返回一个 iterator，遍历把 function argument 应用到 iterable argument 中每个 element 上的结果。

```python
>>> caps = map(lambda x: x.upper(), b_to_k)
>>> next(caps)
'B'
>>> next(caps)
'C'
```

## 4.2.7 用 yield 创建 iterable

在 Python 中，iterator 只对底层系列中的 element 进行一次遍历。在那次遍历之后，每当调用 `__next__`，该 iterator 就会继续抛出 `StopIteration` exception。许多应用需要多次迭代 element。例如，为了枚举所有 element 对，我们必须多次遍历一个 list。

```python
>>> def all_pairs(s):
        for item1 in s:
            for item2 in s:
                yield (item1, item2)
```

```python
>>> list(all_pairs([1, 2, 3]))
[(1, 1), (1, 2), (1, 3), (2, 1), (2, 2), (2, 3), (3, 1), (3, 2), (3, 3)]
```

Sequence 本身并不是 iterator，而是 *iterable* object。Python 中的 iterable interface 由单一消息 `__iter__` 组成，它返回一个 iterator。Python 中内置的 sequence 类型在它们的 `__iter__` method 被调用时返回新的 iterator instance。如果一个 iterable object 每次调用 `__iter__` 时都返回一个全新的 iterator instance，那么它就可以被多次迭代。

通过实现 iterable interface，可以定义新的 iterable class。例如，下面这个 *iterable* 的 `LettersWithYield` class 每次调用 `__iter__` 时都会返回一个新的遍历字母的 iterator。

```python
>>> class LettersWithYield:
        def __init__(self, start='a', end='e'):
            self.start = start
            self.end = end
        def __iter__(self):
            next_letter = self.start
            while next_letter < self.end:
                yield next_letter
                next_letter = chr(ord(next_letter)+1)
```

`__iter__` method 是一个 generator function；它返回一个 generator object，该 object 依次 yield 字母 `'a'` 到 `'d'`，然后停止。每次我们调用这个 method，都会有一个新的 generator 开始对顺序数据做一次全新的遍历。

```python
>>> letters = LettersWithYield()
>>> list(all_pairs(letters))[:5]
[('a', 'a'), ('a', 'b'), ('a', 'c'), ('a', 'd'), ('b', 'a')]
```

## 4.2.8 Iterator interface

Python 的 iterator interface 由一个名为 `__next__` 的 method 定义，它返回它所表示的某个底层顺序系列中的下一个 element。为响应 `__next__` 的调用，iterator 可以执行任意计算，以便取回或计算下一个 element。对 `__next__` 的调用会对 iterator 做出变异性的改变：它们推进 iterator 的位置。因此，多次调用 `__next__` 会返回底层系列中依次出现的 element。Python 在调用 `__next__` 期间抛出 `StopIteration` exception 来表示底层系列已经到达末尾。

下面的 `LetterIter` class 迭代一个底层字母系列，从某个 `start` 字母开始，直到某个 `end` 字母为止（不包含它）。instance attribute `next_letter` 存储下一个要返回的字母。`__next__` method 返回这个字母，并用它计算新的 `next_letter`。

```python
>>> class LetterIter:
        """An iterator over letters of the alphabet in ASCII order."""
        def __init__(self, start='a', end='e'):
            self.next_letter = start
            self.end = end
        def __next__(self):
            if self.next_letter == self.end:
                raise StopIteration
            letter = self.next_letter
            self.next_letter = chr(ord(letter)+1)
            return letter
```

使用这个 class，我们可以用 `__next__` method 或内置的 `next` function（它在自己的 argument 上调用 `__next__`）来顺序访问字母。

```python
>>> letter_iter = LetterIter()
>>> letter_iter.__next__()
'a'
>>> letter_iter.__next__()
'b'
>>> next(letter_iter)
'c'
>>> letter_iter.__next__()
'd'
>>> letter_iter.__next__()
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 12, in next
StopIteration
```

Iterator 是 mutable 的：在推进的过程中，它们追踪某个底层值 sequence 中的位置。当到达末尾时，iterator 就被用尽了。一个 `LetterIter` instance 只能被迭代一次。在它的 `__next__()` method 抛出 `StopIteration` exception 之后，从此以后它都会继续如此。通常，iterator 不会被重置；相反，会创建一个新的 instance 来开始一次新的迭代。

iterator 还允许我们通过实现一个从不抛出 `StopIteration` exception 的 `__next__` method 来表示无限系列。例如，下面 `Positives` class 迭代正整数的无限系列。Python 中内置的 `next` function 会在它的 argument 上调用 `__next__` method。

```python
>>> class Positives:
        def __init__(self):
            self.next_positive = 1;
        def __next__(self):
            result = self.next_positive
            self.next_positive += 1
            return result
>>> p = Positives()
>>> next(p)
1
>>> next(p)
2
>>> next(p)
3
```

## 4.2.10 Python stream

*Stream* 提供了另一种隐式地表示顺序数据的方式。一个 stream 是一个惰性计算的 linked list。像第 2 章的 `Link` class 一样，`Stream` instance 会响应对其 `first` element 和 stream 的 `rest` 的请求。与 `Link` 一样，`Stream` 的 `rest` 本身也是一个 `Stream`。与 `Link` 不同的是，stream 的 `rest` 只在被查找时才计算，而不是提前存储。也就是说，stream 的 `rest` 是惰性计算的。

为了实现这种 lazy evaluation，stream 存储了一个计算 stream 其余部分的 function。每当这个 function 被调用时，它返回的值就在一个名为 `_rest` 的 attribute 中作为 stream 的一部分被 cache 起来；这个名字带有下划线，表示不应直接访问它。

可访问的 attribute `rest` 是一个 property method，它返回 stream 的其余部分，并在必要时计算它。通过这种设计，stream 存储的是*如何计算* stream 的其余部分，而不是总是显式地存储其余部分。

```python
>>> class Stream:
        """A lazily computed linked list."""
        class empty:
            def __repr__(self):
                return 'Stream.empty'
        empty = empty()
        def __init__(self, first, compute_rest=lambda: empty):
            assert callable(compute_rest), 'compute_rest must be callable.'
            self.first = first
            self._compute_rest = compute_rest
        @property
        def rest(self):
            """Return the rest of the stream, computing it if necessary."""
            if self._compute_rest is not None:
                self._rest = self._compute_rest()
                self._compute_rest = None
            return self._rest
        def __repr__(self):
            return 'Stream({0}, <...>)'.format(repr(self.first))
```

linked list 是用嵌套的 expression 定义的。例如，我们可以如下创建一个表示 element 1 然后 5 的 `Link`：

```python
>>> r = Link(1, Link(2+3, Link(9)))
```

同样，我们可以创建一个表示同一系列的 `Stream`。`Stream` 实际上直到请求 stream 的其余部分时才计算第二个 element 5。我们通过创建匿名 function 来实现这一效果。

```python
>>> s = Stream(1, lambda: Stream(2+3, lambda: Stream(9)))
```

这里，1 是 stream 的第一个 element，紧随其后的 `lambda` expression 返回一个计算 stream 其余部分的 function。

访问 linked list `r` 和 stream `s` 的 element 的过程相似。然而，5 存储在 `r` 中，而对于 `s`，它是在第一次被请求时通过加法按需计算出来的。

```python
>>> r.first
1
>>> s.first
1
>>> r.rest.first
5
>>> s.rest.first
5
>>> r.rest
Link(5, Link(9))
>>> s.rest
Stream(5, <...>)
```

`r` 的 `rest` 是一个两 element 的 linked list，而 `s` 的 `rest` 包含一个用于计算其余部分的 function；它将会返回空 stream 这一事实可能尚未被发现。

当 `Stream` instance 被构造时，字段 `self._rest` 是 `None`，表示 `Stream` 的其余部分尚未被计算。当通过点 expression 请求 `rest` attribute 时，`rest` property method 被调用，从而用 `self._rest = self._compute_rest()` 触发计算。由于 `Stream` 内部的 cache 机制，`compute_rest` function 只会被调用一次，然后就被丢弃。

`compute_rest` function 的本质属性是：它不接受任何 argument，并且返回一个 `Stream` 或 `Stream.empty`。

Lazy evaluation 让我们能够用 stream 表示无限的顺序数据集。例如，我们可以表示从任意 `first` 值开始递增的整数。

```python
>>> def integer_stream(first):
        def compute_rest():
            return integer_stream(first+1)
        return Stream(first, compute_rest)
```

```python
>>> positives = integer_stream(1)
>>> positives
Stream(1, <...>)
>>> positives.first
1
```

当 `integer_stream` 第一次被调用时，它返回一个 stream，其 `first` 是该 sequence 中的第一个整数。然而，`integer_stream` 实际上是 recursive 的，因为这个 stream 的 `compute_rest` 会用一个递增后的 argument 再次调用 `integer_stream`。我们说 `integer_stream` 是惰性的，因为只有在请求整数 stream 的 `rest` 时，才会进行对 `integer_stream` 的 recursive 调用。

```python
>>> positives.first
1
>>> positives.rest.first
2
>>> positives.rest.rest
Stream(3, <...>)
```

操作 sequence 的那两个 higher-order function —— `map` 和 `filter` —— 同样适用于 stream，只不过它们的实现必须改变，以便惰性地应用它们的 argument function。`map_stream` function 把一个 function 映射到一个 stream 上，从而产生一个新的 stream。局部定义的 `compute_rest` function 确保每当计算 rest 时，都会把该 function 映射到 stream 的剩余部分上。

```python
>>> def map_stream(fn, s):
        if s is Stream.empty:
            return s
        def compute_rest():
            return map_stream(fn, s.rest)
        return Stream(fn(s.first), compute_rest)
```

可以通过定义一个把 filter function 应用到 stream 其余部分的 `compute_rest` function 来过滤 stream。如果 filter function 拒绝 stream 的第一个 element，那么其余部分会立即被计算。由于 `filter_stream` 是 recursive 的，其余部分可能会被计算多次，直到找到有效的 `first` element。

```python
>>> def filter_stream(fn, s):
        if s is Stream.empty:
            return s
        def compute_rest():
            return filter_stream(fn, s.rest)
        if fn(s.first):
            return Stream(s.first, compute_rest)
        else:
            return compute_rest()
```

`map_stream` 和 `filter_stream` function 展示了 stream 处理中的一个常见模式：局部定义的 `compute_rest` function 在每次计算 rest 时，都会 recursively 地把一个处理 function 应用到 stream 的其余部分上。

为了查看 stream 的内容，我们可以把前 `k` 个 element 转换成一个 Python `list`。

```python
>>> def first_k_as_list(s, k):
        first_k = []
        while s is not Stream.empty and k > 0:
            first_k.append(s.first)
            s, k = s.rest, k-1
        return first_k
```

这些便利的 function 让我们可以用一个简单的例子来验证我们的 `map_stream` 实现，该例子把 3 到 7 的整数平方。

```python
>>> s = integer_stream(3)
>>> s
Stream(3, <...>)
>>> m = map_stream(lambda x: x*x, s)
>>> m
Stream(9, <...>)
>>> first_k_as_list(m, 5)
[9, 16, 25, 36, 49]
```

我们可以用 `filter_stream` function 借助埃拉托斯特尼筛法（sieve of Eratosthenes）定义一个素数 stream，它过滤一个整数 stream，去掉所有是其第一个 element 的倍数的数。通过依次用每个素数过滤，所有合数都会从 stream 中被移除。

```python
>>> def primes(pos_stream):
        def not_divible(x):
            return x % pos_stream.first != 0
        def compute_rest():
            return primes(filter_stream(not_divible, pos_stream.rest))
        return Stream(pos_stream.first, compute_rest)
```

通过截断 `primes` stream，我们可以枚举素数的任意前缀。

```python
>>> prime_numbers = primes(integer_stream(2))
>>> first_k_as_list(prime_numbers, 7)
[2, 3, 5, 7, 11, 13, 17]
```

Stream 与 iterator 形成对比：stream 可以多次传给 pure function，并且每次都 yield 相同的结果。primes stream 不会因为被转换成一个 list 而被“用尽”。也就是说，在把 stream 的前缀转换成一个 list 之后，`prime_numbers` 的 `first` element 仍然是 2。

```python
>>> prime_numbers.first
2
```

正如 linked list 提供了 sequence abstraction 的一种简单实现，stream 提供了一种简单的、函数式的、recursive 的数据结构，它通过使用 higher-order function 来实现 lazy evaluation。

# 第 3 章：解释计算机程序

## 3.1 引言

第 1 章和第 2 章描述了编程中两个基本要素——function 与数据——之间的紧密联系。我们看到了如何用 higher-order function 把 function 当作数据来操作，也看到了如何借助 message passing 和 object 系统为数据赋予行为。我们还学习了组织大型程序的技术，例如 functional abstraction、data abstraction、class inheritance 和 generic function。这些核心概念构成了坚实的基础，我们可以在其上构建模块化、可维护、可扩展的程序。

本章关注编程的第三个基本要素：程序本身。一个 Python 程序不过是一段文本。只有通过解释的过程，我们才能基于这段文本执行任何有意义的计算。像 Python 这样的编程语言之所以有用，是因为我们可以定义一个 *interpreter*，也就是执行 Python 的 evaluation 和运行过程的程序。毫不夸张地说，这是编程中最根本的观念：决定编程语言中 expression 含义的 interpreter，本身也不过是另一个程序。

领会这一点，就会改变我们作为程序员的自我形象。我们开始把自己看作语言的设计者，而不仅仅是由他人设计的语言的使用者。

### 3.1.1 编程语言

各种编程语言在语法结构、特性和应用领域上差异极大。在通用编程语言中，function 定义和 function 应用这两种构造无处不在。另一方面，也有一些功能强大却只包含极少特性的语言，它们没有 object 系统、没有 higher-order function、没有赋值，甚至没有 `while` 和 `for` statement 这样的控制构造。作为特性极简而功能强大的语言的一个例子，我们将介绍 [Scheme](https://en.wikipedia.org/wiki/Scheme_(programming_language)) 编程语言。本教材介绍的 Scheme 子集完全不允许 mutable 的值。

本章研究 interpreter 的设计，以及它们在运行程序时所产生的计算过程。为一门通用编程语言设计 interpreter 这件事，乍看之下可能令人生畏。毕竟，interpreter 是能够根据输入执行任何可能计算的程序。然而，许多 interpreter 都有一种优雅的共同结构：两个相互 recursive 的 function。第一个在 environment 中 evaluate expression，第二个把 function 应用到 argument 上。

这些 function 之所以是 recursive 的，是因为它们相互定义：应用一个 function 需要 evaluate 其 body 中的 expression，而 evaluate 一个 expression 又可能涉及应用一个或多个 function。

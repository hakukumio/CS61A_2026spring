# 3.3 exception

程序员必须时刻留意程序中可能出现的各种错误。这样的例子比比皆是：一个 function 可能收到它并不打算接受的 argument，所需的资源可能缺失，或者跨越网络的连接可能中断。设计程序时，必须预见到可能出现的异常情况，并采取恰当的措施来处理它们。

处理程序中的错误没有唯一正确的做法。像 web 服务器这样提供持续服务的程序应当对错误保持健壮，把错误记录下来供日后检查，同时尽可能继续处理新的请求。另一方面，Python interpreter 处理错误的方式是立即终止并打印错误信息，这样程序员就能在问题出现时尽快解决。无论如何，程序员都必须有意识地选择程序应如何应对异常情况。

*exception* 是本节的主题，它为程序添加错误处理逻辑提供了一种通用机制。*抛出 exception* 是一种技术：它中断程序中正常的运行流程，表明出现了某种异常情况，并直接返回到程序中指定用于响应该情况的外层部分。Python interpreter 每次在 expression 或 statement 中检测到错误时都会抛出一个 exception。用户也可以使用 `raise` 和 `assert` statement 抛出 exception。

**抛出 exception。**exception 是一个 object instance，它所属的 class 直接或间接继承自 `BaseException` class。第 1 章介绍的 `assert` statement 会抛出一个 class 为 `AssertionError` 的 exception。一般来说，任何 exception instance 都可以用 `raise` statement 抛出。raise statement 的一般形式在 [Python 文档](http://docs.python.org/py3k/reference/simple_stmts.html#raise) 中描述。`raise` 最常见的用法是构造一个 exception instance 并抛出它。

```python
>>> raise Exception('An error occurred')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
Exception: an error occurred
```

当 exception 被抛出时，当前代码块中后续的 statement 都不会执行。除非该 exception 被*处理*（见下文），否则 interpreter 会直接返回到交互式 read-eval-print loop；如果 Python 是以文件参数启动的，则会完全终止。此外，interpreter 还会打印一份 *stack backtrace*，它是一段结构化的文本，描述了抛出 exception 的那条运行分支中当前活动的 function 调用嵌套集合。在上面的例子中，文件名 `<stdin>` 表明该 exception 是用户在交互式会话中抛出的，而不是来自文件中的代码。

**处理 exception。**exception 可以由外层的 `try` statement 处理。一个 `try` statement 由多个子句组成；第一个以 `try` 开头，其余的以 `except` 开头：

```

try:
    <try suite>
except <exception class> as <name>:
    <except suite>
...
```

`<try suite>` 总是在 `try` statement 执行时立即执行。`except` 子句的 suite 只有在执行 `<try suite>` 的过程中抛出了 exception 时才会执行。每个 `except` 子句都指定了要处理的特定 exception class。例如，如果 `<exception class>` 是 `AssertionError`，那么在执行 `<try suite>` 过程中抛出的、继承自 `AssertionError` 的任何 class 的 instance，都会由随后的 `<except suite>` 处理。在 `<except suite>` 内，标识符 `<name>` 被绑定到抛出的那个 exception object，但这一 binding 不会延续到 `<except suite>` 之外。

例如，我们可以用一个 `try` statement 来处理 `ZeroDivisionError` exception，在 exception 抛出时把名字 `x` 绑定到 0。

```python
>>> try:
        x = 1/0
    except ZeroDivisionError as e:
        print('handling a', type(e))
        x = 0
handling a <class 'ZeroDivisionError'>
>>> x
0
```

`try` statement 会处理在 `<try suite>` 内被应用（无论直接还是间接）的 function 的 body 中发生的 exception。当 exception 被抛出时，控制权会直接跳到最近的、能处理该类 exception 的 `try` statement 的 `<except suite>` 的 body。

```python
>>> def invert(x):
        result = 1/x  # Raises a ZeroDivisionError if x is 0
        print('Never printed if x is 0')
        return result
```

```python
>>> def invert_safe(x):
        try:
            return invert(x)
        except ZeroDivisionError as e:
            return str(e)
```

```python
>>> invert_safe(2)
Never printed if x is 0
0.5
>>> invert_safe(0)
'division by zero'
```

这个例子说明，`invert` 中的 `print` expression 从未被 evaluate，控制权转而转移到 `invert_safe` 中 `except` 子句的 suite。把 `ZeroDivisionError` 的 `e` 转换成 string，就得到了 `invert_safe` 返回的、便于人阅读的 string：`'division by zero'`。

## 3.3.1 exception object

exception object 本身也可以有 attribute，例如 `assert` statement 中给出的错误消息，以及关于 exception 在执行过程的何处被抛出的信息。用户自定义的 exception class 可以有额外的 attribute。

在第 1 章中，我们实现了牛顿法来求任意 function 的零点。下面的例子定义了一个 exception class，它在出现 `ValueError` 时返回迭代改进过程中找到的最佳猜测值。当 `sqrt` 被应用于负数时会抛出数学域错误（`ValueError` 的一种）。这个 exception 的处理方式是抛出一个 `IterImproveError`，它把牛顿法得到的最近一次猜测值存为 attribute。

首先，我们定义一个继承自 `Exception` 的新 class。

```python
>>> class IterImproveError(Exception):
        def __init__(self, last_guess):
            self.last_guess = last_guess
```

接下来，我们定义 `improve` 的一个版本，也就是我们那个通用的迭代改进算法。这个版本通过抛出一个存储最近一次猜测值的 `IterImproveError` 来处理任何 `ValueError`。和之前一样，`improve` 接受两个 function 作为 argument，每个 function 接受一个数值 argument。`update` function 返回新的猜测值，而 `done` function 返回一个布尔值，表示改进过程是否已经收敛到正确的值。

```python
>>> def improve(update, done, guess=1, max_updates=1000):
        k = 0
        try:
            while not done(guess) and k < max_updates:
                guess = update(guess)
                k = k + 1
            return guess
        except ValueError:
            raise IterImproveError(guess)
```

最后，我们定义 `find_zero`，它返回把 `improve` 应用于由 `newton_update` 返回的牛顿更新 function 之后的结果；后者定义于第 1 章，在本例中无需改动。这个版本的 `find_zero` 通过返回最近一次猜测值来处理 `IterImproveError`。

```python
>>> def find_zero(f, guess=1):
        def done(x):
            return f(x) == 0
        try:
            return improve(newton_update(f), done, guess)
        except IterImproveError as e:
            return e.last_guess
```

考虑把 `find_zero` 应用于求 function $2x^2 + \sqrt{x}$ 的零点。这个 function 在 0 处有一个零点，但把任何负数代入它都会抛出一个 `ValueError`。我们在第 1 章实现的牛顿法会抛出这个错误，无法返回任何零点的猜测值。修订后的实现会返回错误出现之前找到的最近一次猜测值。

```python
>>> from math import sqrt
>>> find_zero(lambda x: 2*x*x + sqrt(x))
-0.030211203830201594
```

尽管这个近似值距离正确答案 0 还很远，但有些应用宁愿接受这种粗略的近似，也不愿得到 `ValueError`。

exception 是另一种技术，帮助我们编写的程序把关注点分离成模块化的部分。在这个例子中，Python 的 exception 机制让我们得以把迭代改进的逻辑（它在 `try` 子句的 suite 中原封不动地出现）与处理错误的逻辑（它出现在 `except` 子句中）分离开来。我们还会发现，在用 Python 实现 interpreter 时，exception 是一个很有用的特性。

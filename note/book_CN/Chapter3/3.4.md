# 3.4 组合式语言的 Interpreter

我们现在开始考察一门技术：用它可以把语言建立在其他语言之上。*元语言 abstraction* —— 建立新的语言 —— 在工程设计的各个分支中都扮演着重要角色。它对计算机编程尤为重要，因为在编程中，我们不仅可以构造新的语言，还可以通过构造 interpreter 来实现这些语言。一门编程语言的 interpreter 是一个 function：当它被应用到该语言的一个 expression 上时，它会执行求值该 expression 所需的动作。

我们将首先为一门称为 Calculator 的语言定义一个 interpreter，它是 Scheme 的一个受限的子集。然后，我们将为整个 Scheme 勾画一个 interpreter 的草图。我们创建的 interpreter 将是完备的，也就是说，它允许我们用 Scheme 编写完全通用的程序。为此，它将实现与我们在第 1 章为 Python 程序引入的相同的 environment 求值模型。

本节中的许多例子都包含在配套的 [Scheme-Syntax Calculator 示例](../examples/scalc/scalc.html) 中，因为它们太复杂，无法自然地放进本文的体例中。

## 3.4.1 一个 Scheme-Syntax Calculator

Scheme-Syntax Calculator（简称 Calculator）是一门用于加、减、乘、除算术运算的 expression 语言。Calculator 与 Scheme 共享相同的 call expression 语法和 operator 行为。加法（`+`）和乘法（`*`）运算各接受任意数量的 argument：

```

> (+ 1 2 3 4)
10
> (+)
0
> (* 1 2 3 4)
24
> (*)
1
```

减法（`-`）有两种行为。有一个 argument 时，它对该 argument 取负。至少有两个 argument 时，它从第一个 argument 中减去其余的所有 argument。除法（`/`）也有一对类似的行为：计算单个 argument 的乘法逆元，或者用第一个 argument 除以其余的所有 argument：

```

> (- 10 1 2 3)
4
> (- 3)
-3
> (/ 15 12)
1.25
> (/ 30 5 2)
3
> (/ 10)
0.1
```

call expression 的求值方式是：先对它的 operand 子 expression 求值，然后把 operator 应用到得到的 argument 上：

```

> (- 100 (* 7 (+ 8 (/ -12 -3))))
16.0
```

我们将用 Python 实现一个 Calculator 语言的 interpreter。也就是说，我们将编写一个 Python 程序，它把字符串行作为输入，并返回把这些行当作一个 Calculator expression 求值的结果。如果 calculator expression 的形式不正确，我们的 interpreter 会抛出适当的异常。

## 3.4.2 Expression 树

在本课程此前的学习中，expression 树一直是我们描述求值过程时提到的概念性实体；我们从未在程序中把 expression 树显式地表示为数据。为了编写 interpreter，我们必须把 expression 当作数据来操作。

在 Calculator 中，primitive expression 就是一个数字或一个字符串：要么是 `int` 或 `float`，要么是一个 operator 符号。所有组合起来的 expression 都是 call expression。一个 call expression 是一个 Scheme list，它的第一个元素是 operator，后面跟着零个或多个 operand expression。

**Scheme Pair。** 在 Scheme 中，list 是嵌套的 pair，但并非所有 pair 都是 list。为了在 Python 中表示 Scheme 的 pair 和 list，我们将定义一个 class `Pair`，它类似于本章前面出现的 `Rlist` class。其实现见 [scheme_reader](../examples/scalc/scheme_reader.py.html)。

空 list 由一个称为 `nil` 的 object 表示，它是 class `nil` 的一个 instance。我们假定只会创建唯一一个 `nil` instance。

`Pair` class 和 `nil` object 是在 Python 中表示的 Scheme 值。它们的 `repr` 字符串是 Python expression，`str` 字符串是 Scheme expression。

```python
>>> s = Pair(1, Pair(2, nil))
>>> s
Pair(1, Pair(2, nil))
>>> print(s)
(1 2)
```

它们实现了 Python 中基本的 sequence 接口，即长度和元素选择，还实现了一个返回 Scheme list 的 `map` method。

```python
>>> len(s)
2
>>> s[1]
2
>>> print(s.map(lambda x: x+4))
(5 6)
```

**嵌套 List。** 嵌套的 pair 可以表示 list，但 list 的元素本身也可以是 list。因此，pair 足以表示 Scheme expression，而 Scheme expression 实际上就是嵌套的 list。

```python
>>> expr = Pair('+', Pair(Pair('*', Pair(3, Pair(4, nil))), Pair(5, nil)))
>>> print(expr)
(+ (* 3 4) 5)
>>> print(expr.second.first)
(* 3 4)
>>> expr.second.first.second.first
3
```

这个例子说明，所有 Calculator expression 都是嵌套的 Scheme list。我们的 Calculator interpreter 会读入嵌套的 Scheme list，把它们转换为以嵌套 `Pair` instance 表示的 expression 树（见下文*解析 expression*），然后对 expression 树求值以产生值（见下文*Calculator 求值*）。

## 3.4.3 解析 Expression

解析是从原始文本输入生成 expression 树的过程。一个解析器由两个组件组合而成：一个词法分析器和一个语法分析器。首先，*词法分析器* 把输入字符串划分成 *token*，token 是语言中最小的语法单位，例如名字和符号。其次，*语法分析器* 根据这个 token 序列构造 expression 树。词法分析器产生的 token 序列由语法分析器消费。

**词法分析。** 把字符串解释为 token 序列的组件称为 *分词器* 或 *词法分析器*。在我们的实现中，分词器是 [scheme_tokens](../examples/scalc/scheme_tokens.py.html) 中一个名为 `tokenize_line` 的 function。Scheme 的 token 由空白、括号、点或单引号分隔。分隔符本身也是 token，符号和数字也是 token。分词器逐字符地分析一行，验证符号和数字的格式。

对一个形式正确的 Calculator expression 做分词，会分离出所有符号和分隔符，同时识别出多字符的数字（例如 2.3）并把它们转换成数值类型。

```python
>>> tokenize_line('(+ 1 (* 2.3 45))')
['(', '+', 1, '(', '*', 2.3, 45, ')', ')']
```

词法分析是一个迭代过程，它可以独立地应用于输入程序的每一行。

**语法分析。** 把 token 序列解释为 expression 树的组件称为 *语法分析器*。语法分析是一个 tree recursion 的过程，它必须考虑可能跨越多行的整个 expression。

语法分析由 [scheme_reader](../examples/scalc/scheme_reader.py.html) 中的 `scheme_read` function 实现。它之所以是 tree recursion 的，是因为分析一个 token 序列往往涉及把其中的一个子序列分析成一个子 expression，而这个子 expression 本身又充当更大的 expression 树的一个分支（例如 operand）。recursion 生成了由 evaluator 消费的层次结构。

`scheme_read` function 期望它的输入 `src` 是一个 `Buffer` instance，它提供对 token 序列的访问。定义在 [buffer](../examples/scalc/buffer.py.html) 模块中的 `Buffer`，会把跨越多行的 token 收集到一个 object 中，以便对它进行语法分析。

```python
>>> lines = ['(+ 1', '   (* 2.3 45))']
>>> expression = scheme_read(Buffer(tokenize_lines(lines)))
>>> expression
Pair('+', Pair(1, Pair(Pair('*', Pair(2.3, Pair(45, nil))), nil)))
>>> print(expression)
(+ 1 (* 2.3 45))
```

`scheme_read` function 首先检查各种 base case，包括空输入（它会抛出一个文件结束异常，在 Python 中称为 `EOFError`）和 primitive expression。每当一个 `(` token 表示一个 list 的开头时，就会递归地调用 `read_tail`。

`read_tail` function 继续从同一个输入 `src` 中读取，但它期望在一个 list 已经开始之后被调用。它的 base case 是空输入（一个错误）或终止该 list 的右括号。它的递归调用用 `scheme_read` 读取 list 的第一个元素，用 `read_tail` 读取 list 的其余部分，然后返回一个用 `Pair` 表示的 list。

`scheme_read` 的这个实现可以读取形式正确的 Scheme list，而这正是 Calculator 语言所需要的全部。解析 dotted list 和 quoted form 留作练习。

信息丰富的语法错误能大幅提升 interpreter 的可用性。抛出的 `SyntaxError` 异常会包含对所遇问题的描述。

## 3.4.4 Calculator 求值

[scalc](../examples/scalc/scalc.py.html) 模块实现了 Calculator 语言的一个 evaluator。`calc_eval` function 接受一个 expression 作为 argument 并返回它的值。`simplify`、`reduce` 和 `as_scheme_list` 这几个 helper function 的定义出现在 model 中，并在下面使用。

对 Calculator 来说，expression 只有两种合法的语法形式：数字和 call expression，后者是表示形式正确的 Scheme list 的 `Pair` instance。数字是 *self-evaluating* 的；它们可以直接从 `calc_eval` 返回。call expression 则需要进行 function application。

```python
>>> def calc_eval(exp):
        """Evaluate a Calculator expression."""
        if type(exp) in (int, float):
            return simplify(exp)
        elif isinstance(exp, Pair):
            arguments = exp.second.map(calc_eval)
            return simplify(calc_apply(exp.first, arguments))
        else:
            raise TypeError(exp + ' is not a number or call expression')
```

call expression 的求值方式是：先把 `calc_eval` function 递归地 map 到 operand 的 list 上，从而计算出一个 `arguments` 的 list。然后，在第二个 function `calc_apply` 中把 operator 应用到这些 argument 上。

Calculator 语言足够简单，我们可以轻松地把应用每个 operator 的逻辑写在一个 function 的体内。在 `calc_apply` 中，每个条件子句对应一个 operator 的应用。

```python
>>> def calc_apply(operator, args):
        """Apply the named operator to a list of args."""
        if not isinstance(operator, str):
            raise TypeError(str(operator) + ' is not a symbol')
        if operator == '+':
            return reduce(add, args, 0)
        elif operator == '-':
            if len(args) == 0:
                raise TypeError(operator + ' requires at least 1 argument')
            elif len(args) == 1:
                return -args.first
            else:
                return reduce(sub, args.second, args.first)
        elif operator == '*':
            return reduce(mul, args, 1)
        elif operator == '/':
            if len(args) == 0:
                raise TypeError(operator + ' requires at least 1 argument')
            elif len(args) == 1:
                return 1/args.first
            else:
                return reduce(truediv, args.second, args.first)
        else:
            raise TypeError(operator + ' is an unknown operator')
```

上面，每个 suite 计算不同 operator 的结果，或者在给出的 argument 数量不对时抛出适当的 `TypeError`。`calc_apply` function 可以直接应用，但必须把一个 *值* 的 list 而不是 operand expression 的 list 作为 argument 传给它。

```python
>>> calc_apply('+', as_scheme_list(1, 2, 3))
6
>>> calc_apply('-', as_scheme_list(10, 1, 2, 3))
4
>>> calc_apply('*', nil)
1
>>> calc_apply('*', as_scheme_list(1, 2, 3, 4, 5))
120
>>> calc_apply('/', as_scheme_list(40, 5))
8.0
```

`calc_eval` 的作用是正确地调用 `calc_apply`：它先计算 operand 子 expression 的值，再把它们作为 argument 传给 `calc_apply`。因此，`calc_eval` 可以接受嵌套的 expression。

```python
>>> print(exp)
(+ (* 3 4) 5)
>>> calc_eval(exp)
17
```

`calc_eval` 的结构是 dispatch on type 的一个例子：也就是根据 expression 的形式进行 dispatch。第一种 expression 形式是数字，它不需要额外的求值步骤。一般来说，不需要额外求值步骤的 primitive expression 称为 *self-evaluating*。在我们的 Calculator 语言中，唯一 self-evaluating 的 expression 是数字，但一门通用的编程语言还可能包含 string、布尔值等。

**Read-eval-print loop。** 与 interpreter 交互的典型方式是通过 read-eval-print loop，即 REPL，它是一种交互模式：读取一个 expression、对它求值，并把结果打印给用户。Python 交互式会话就是这样一个 loop 的例子。

REPL 的实现可以在很大程度上独立于它所使用的 interpreter。下面的 function `read_eval_print_loop` 缓冲来自用户的输入，用特定于语言的 `scheme_read` function 构造一个 expression，然后打印把 `calc_eval` 应用到该 expression 上的结果。

```python
>>> def read_eval_print_loop():
        """Run a read-eval-print loop for calculator."""
        while True:
            src = buffer_input()
            while src.more_on_line:
                expression = scheme_read(src)
                print(calc_eval(expression))
```

这个版本的 `read_eval_print_loop` 包含了交互式界面的所有基本组件。一个示例会话如下：

```

> (* 1 2 3)
6
> (+)
0
> (+ 2 (/ 4 8))
2.5
> (+ 2 2) (* 3 3)
4
9
> (+ 1
     (- 23)
     (* 4 2.5))
-12
```

这个 loop 实现没有任何终止或错误处理机制。我们可以通过向用户报告错误来改进界面。我们还可以让用户通过发出键盘中断（在 UNIX 上是 `Control-C`）或文件结束异常（在 UNIX 上是 `Control-D`）来退出 loop。为了实现这些改进，我们把 `while` statement 原来的 suite 放进一个 `try` statement 中。第一个 `except` 子句处理 `scheme_read` 抛出的 `SyntaxError` 和 `ValueError` 异常，以及 `calc_eval` 抛出的 `TypeError` 和 `ZeroDivisionError` 异常。

```python
>>> def read_eval_print_loop():
        """Run a read-eval-print loop for calculator."""
        while True:
            try:
                src = buffer_input()
                while src.more_on_line:
                    expression = scheme_read(src)
                    print(calc_eval(expression))
            except (SyntaxError, TypeError, ValueError, ZeroDivisionError) as err:
                print(type(err).__name__ + ':', err)
            except (KeyboardInterrupt, EOFError):  # <Control>-D, etc.
                print('Calculation completed.')
                return
```

这个 loop 实现会报告错误而不退出 loop。发生错误时不退出程序，而是在打印错误信息后重新开始 loop，这样用户就能修改他们的 expression。导入 `readline` 模块后，用户甚至可以用上箭头或 `Control-P` 调出之前输入过的内容。最终版本提供了一个信息丰富的错误报告界面：

```

> )
SyntaxError: unexpected token: )
> 2.3.4
ValueError: invalid numeral: 2.3.4
> +
TypeError: + is not a number or call expression
> (/ 5)
TypeError: / requires exactly 2 arguments
> (/ 1 0)
ZeroDivisionError: division by zero
```

当我们把 interpreter 推广到 Calculator 之外的新语言时，我们会看到 `read_eval_print_loop` 是由一个解析 function、一个求值 function，以及 `try` statement 所处理的异常类型来参数化的。除了这些变化之外，所有 REPL 都可以用相同的结构来实现。
